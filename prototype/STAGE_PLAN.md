# 阶段计划(Stage Plan)

**目标**:给定持续增长的录屏视频库,自动产出可执行、可验证的 Mock 操作程序 —— 复现的是**过程**(同命令、同顺序、同参数),不是"看懂结果后另找一条路做出同样的东西"。

**当前载体**是 AutoCAD 教学视频 → CAD 图纸;但阶段划分与工具契约是软件无关的,换成别的桌面软件只需替换 S5 的执行后端与 S6 的校验后端。

---

## 0. 阶段总览

```
      视频库(持续增长)
            │
  S0 ┌──────▼──────┐  discover   增量扫描 → 课时清单        [自动]
     └──────┬──────┘
  S1 ┌──────▼──────┐  probe      CV 全片探测 → 证据包        [自动·CV]
     └──────┬──────┘
  S2 ┌──────▼──────┐  read       读命令流 → 命令与参数        [Agent]
     └──────┬──────┘
  S3 ┌──────▼──────┐  measure    终态几何测量 → geo.json      [自动·CV]
     └──────┬──────┘
  S4 ┌──────▼──────┐  build      生成回放脚本 → lN.scr        [Agent + 自动]
     └──────┬──────┘
  S5 ┌──────▼──────┐  replay     AutoCAD 回放 → lN.dwg/.dxf   [自动]
     └──────┬──────┘
  S6 ┌──────▼──────┐  verify     校验 → verify.json           [自动]
     └──────┬──────┘
     主控验收 + 清单归档
```

**分界线**:CV 只回答"哪里、什么时候、什么范围变了";Agent 负责一切"看懂"——**包括看懂字**(命令行文字、按钮文字、对话框数值)。CV 层零 OCR、零 VLM。

## S0 discover / watch —— 增量发现与持续接活

视频是**持续到货**的,所以这一层有两种用法:

```powershell
py -3.11 cadrep.py discover              # 手动扫一次
py -3.11 cadrep.py watch                 # 常驻: 每 180s 重扫, 新课自动跑 S1
py -3.11 cadrep.py watch --once          # 只看一眼当前状态
py -3.11 cadrep.py watch --no-probe      # 只报告新课, 不自动探测
```

`watch` 的行为:
- 每轮重扫视频目录,**`.aria2` 伴随文件还在 = 没下完 → 跳过,下一轮再看**;
- 新出现的已编号课时立即跑 S1(CV 全片探测),跑完打印提示并列出待建模清单;
- S2 起需要 Agent 介入,`watch` 只负责备料,不会自作主张往下走。

这样新视频到货后不必人工触发,流水线自己接住第一棒。

## S1 probe —— CV 全片探测

| 项 | 内容 |
|---|---|
| 执行 | `py -3.11 cadrep.py probe <N...>` 或 `--todo --limit K` |
| 耗时 | 约 3–6 分钟/课(15 分钟视频),CPU 密集,可并行 |
| 产物 | `lN/cv/` 下 9 项(见下) |
| 完成条件 | `cv/cmdmont/` 非空 |

产物契约(下游只依赖这些):

| 文件 | 内容 |
|---|---|
| `manifest.json` | 视频元数据 + 采用的布局 + 工具版本 + 统计 |
| `trajectory.json` | 逐帧光标 `{f,t,x,y,sx,sy,found,mode}` |
| `input_events.json` | 输入事件 `{id,t0,fCrop,cursorAt}` |
| `episodes.json` | UI 变化片段 |
| `actions.json` | 候选动作(带类型与依据) |
| `cmdstrips/` | 命令行区域变化条带(原生分辨率,时间序) |
| `cmdmont/` | 条带蒙太奇(每张 16 条),供 Agent 批量读取 |
| `slices/` | 每动作证据包(可选,`--no-slices` 跳过以提速) |
| `index.html` | 人工复核页 |

**布局自适应**:已知分辨率走内置配置;不认识的走 `cv/layout.py` 自动检测(亮度分层定位画布/命令行/功能区,出现率定位按键覆盖层,静止亮竖线定位双视口分隔)。检测结果缓存进 `cv/layout_cache.json`。

## S2 read —— 读命令流(Agent 核心工作)

| 项 | 内容 |
|---|---|
| 执行 | Agent 逐张读 `cv/cmdmont/*.png` |
| 产物 | `lN/commands.md` |
| 覆盖率要求 | **≥60% 的蒙太奇**,且必须覆盖所有带数值参数的时段 |

要提取的三件事:

1. **命令与顺序** —— 用了什么命令,什么先后;
2. **数值参数** —— 命令行回显的半径/长度/角度/间距/份数……这是**最高等级证据**(等同原始输入);
3. **无效操作** —— 取消(`*取消*`)、撤销(`u`)、删除重画(`_erase`),记录时间点但**不进入执行序列**。

这一步目前由 Agent(模型)人工完成。证据包信息量已被验证足够,下一步接 API 自动化即可闭环。

## S3 measure —— 终态几何测量

| 项 | 内容 |
|---|---|
| 执行 | `py -3.11 cadrep.py measure <N> --t <秒>` |
| 产物 | `lN/geo.json` + `lN/geo_overlay.png` |
| 适用 | 徒手绘制(命令行没留下坐标)的内容 |

能力:线段(含共线合并)、圆(圆周支撑验证)、**圆弧角度范围**(逐度支撑扫描)、**椭圆**(轮廓拟合 + 周向验证)。

两条硬规则:
- **必须 `--color white`** —— AutoCAD 深色主题下几何是白色、标注是黄色,这是分离两者的干净信号;
- **必须看 `geo_overlay.png` 人工确认** —— 弹出菜单、ViewCube 会造成误检,不对就换帧或收 ROI。

## S4 build —— 生成回放脚本

| 项 | 内容 |
|---|---|
| 产物 | `lN/lN.scr` |
| 优先级 | **命令行确认的数值 > 像素测量 > 布局排列** |

三条路径:
- 有确切尺寸的图形 → **解析式精确构造**(如"边长100的等边三角形");
- 徒手图形 → `cv/to_scr.py` 把测量结果转脚本(像素→图纸坐标,y 翻转);
- 复杂课(阵列/倒角/修剪/三维)→ Agent 按命令流手写脚本。

输出路径固定,便于 S5/S6 自动接管。

## S5 replay —— 真实软件回放

| 项 | 内容 |
|---|---|
| 执行 | `py -3.11 cadrep.py replay <N>` → `run_lesson.ps1` |
| 后端 | AutoCAD 2027 `accoreconsole.exe`(无头) |
| 产物 | `lN.dwg` + `lN.dxf` + `log.txt` |

**并发安全**:执行器只杀自己启动的进程,绝不 `Stop-Process` 全部 accoreconsole —— 多 agent 并行时会互相打断。每个进程带硬超时,超时即杀并报告。

**无头替代规则**(缺图形管线导致,必须在报告中显式记录):

| 视频命令 | 无头替代 | 原因 |
|---|---|---|
| 快速 TRIM 点选 | 标准模式 + 栏选 `_F` | 点选拾取失败 |
| JOIN | `PEDIT _M` + `_J` | JOIN 首问是单选源对象 |
| PRESSPULL | EXTRUDE | 需面内点击 |
| LOFT 逐个点选 | 只存两截面时 `_ALL` | 投影重叠有歧义 |
| 布尔运算点选 | 点必须在**实体边**上 | 面内点击被当成窗选起点 |
| FILLET `_R` 后接倒角 | 拆成两条命令 | 本版设完半径即退出 |
| PLINE 首个圆弧段 | 圆心 `_CE` 或第二点 `_S` | 方向退化被拒 |
| 渐变填充 | 降级 SOLID(**色阶丢失**) | `-GRADIENT` 不存在;`-HATCH _P _G` 后有无法脚本化的交互 |
| 大型三维 UNION / ZOOM E | 拆开或省略 | 实体规模过大会挂死 |
| 所有对话框命令 | 用 `-` 前缀的命令行版本 | 对话框无人应答会挂死 |

**脚本语法坑**:
- `.scr` 空行 = 回车;**连续空行会重入上一条命令**(行尾空格已是回车,后面再跟空行同样重入)——最高频事故源;
- SAVEAS 目标文件已存在会弹覆盖确认 → 回放前先删旧产物;
- 拾取点必须落在当前 ZOOM 窗口内,否则单点被解释成窗选起点;
- 填充边界检测依赖当前视图 → 填充前先 ZOOM 覆盖全部边界;
- POLYGON 参数顺序:边数 → 中心 → 内接/外切 → 半径。

## S6 verify —— 校验

| 项 | 内容 |
|---|---|
| 执行 | `py -3.11 cadrep.py verify <N>` |
| 产物 | `lN/verify.json` |

四种校验手段,**至少满足两项**:

1. **实体清单** —— DXF 里的实体种类与数量是否与预期一致;
2. **几何摘要** —— 圆心/半径、多段线顶点、椭圆参数;
3. **标注文字回读** —— 回放后由 AutoCAD **自己量出**的 `标注文字 = N` 与视频标注一致(独立旁证,不是脚本输入);
4. **体积/包围盒** —— 三维件用 MASSPROP 对解析计算值(已验证 123/124/125/126 四件全部 0 误差)。

## 证据通道分级(实战总结)

退到像素测量之前,**先找高等级通道** —— 它们给的是精确值,不是估计:

| 通道 | 拿到什么 | 等级 |
|---|---|---|
| **`BOUNDARY` + `LIST`** | 多段线**全部顶点世界坐标** —— 最硬 | C |
| 提示里的 `<默认值>` 回显 | 等于上一次实际用的值 | C |
| `DIMLINEAR`/`DIMCONTINUE` 链 | 尺寸链各段与总长,**链能自闭合即自校验**;缺的段可由闭合方程唯一解出 | C |
| `MEASUREGEOM`/`DIST`/`AREA` | 面积/周长/距离,可反算边长 | C |
| 标注文字回读(回放后) | AutoCAD 自己量出,独立于脚本输入 | D |
| 对话框 / 特性面板 | 设置项、直径/周长/面积/图层/颜色 | D |
| 目标图 / 标题页标注 | 整套规格 | D |
| 终态画布像素测量 | 徒手内容的几何 | M |

**跨集交叉校验**:同一案例多集时,后集的标注链可以**证伪**前集的像素测量。
实例:课时99/100 最初按像素做成 14120×8560,被课时101 的命令行标注链证伪后
按 C 级证据重做为 13500×8430,三集共用同一套轴网才自洽。

## 并发编排的实测教训

| 并发规模 | 结果 |
|---|---|
| 14 个 agent | **日额度被打爆**,全部 429 中断 |
| 4 个 agent | **周额度被打爆** |
| 2 个 agent + 主控自己动手 | 稳定跑完 |

配套约束:agent 不得开后台轮询/monitor;AutoCAD 回放严格串行;
执行器只杀自己启动的进程(绝不 `Stop-Process` 全部 accoreconsole)。

## 验收与证据等级

每课报告必须标注证据等级:

| 记号 | 含义 |
|---|---|
| **C** | 命令行回显确认的数值(等同原始输入,最高) |
| **D** | 标注文字回读(AutoCAD 自己量出,独立旁证) |
| **M** | 终态画布像素测量(已按色相与标注分离) |
| **L** | 布局排列(徒手内容无绝对比例时的呈现选择,非几何推断) |

**做不到的必须显式写出**,不得含糊或编造 —— 例如渐变色阶未复现、某个 OFFSET 未落到几何上、FILLETEDGE 未实现。

## 并行编排

- 一个 Agent 负责 5–8 课,按内容类型分组(绘图 / 修改 / 阵列 / 文字 / 标注 / 表格块图层);
- Agent 先把本组全部 S1 用后台任务排队跑起来,再逐课做 S2–S6,不串行等待;
- **S1/S3 可高度并行**(纯 CPU);**S5 是竞争资源**(AutoCAD 进程),排队变慢属正常,重试而非判失败;
- 主控负责:派工、并发安全约束、验收(跑 `cadrep.py status` + `verify`)、归档清单。
