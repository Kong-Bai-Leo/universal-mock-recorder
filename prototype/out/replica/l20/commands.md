## 验证(verify.json)

```
l20.dxf  counts = { WIPEOUT: 6, LWPOLYLINE: 5, CIRCLE: 1, ARC: 1, ELLIPSE: 1, HATCH: 1 }
CIRCLE = c(3200,300) r 400
ELLIPSE = c(3200,-1400) major(600,0) ratio 0.4167
HATCH  = { pattern: "ANSI31", solid: 0 }
LWPOLYLINE = 矩形1(0,-1000)…(0,-300) 闭合 / 6 边形 / 36 边形 / 60 边形 / 大矩形(0,-3000)…(0,-1800)
```

**逐项自校验**:

1. **`WIPEOUT: 6`** = 3 个点方式 + 2 个 `_P` 方式 + 1 个填充上方的覆盖区 ✓
2. **`LWPOLYLINE: 5` 而不是 6** —— 画了 2 条矩形多段线,
   第 1 条 `_.WIPEOUT _P … _N`(**不删源**)保留,
   第 2 条 `_.WIPEOUT _P … _Y`(**删源**)消失 →
   **`Y/N` 两种答法的差异被实体计数硬性证明**,这是本课最有力的自校验 ✓
3. **正多边形顶点数**:DXF 里三条闭合多段线分别是 **6 / 36 / 60** 个顶点,
   与 378.7s / 697.9s / 723.4s 的命令行 **逐个对上** ✓
4. **内接 vs 外切**:6 边形与 36 边形的顶点到中心距离 = **400**(内接,顶点在圆上);
   60 边形顶点距中心 = 400/cos(π/60) = **400.55**(外切,边中点在圆上)——
   `_I` 与 `_C` 的差异同样被顶点表证明 ✓
   (DXF 60 边形首点 `(4579.0369, −1300.0)`,距中心 (4600,−1700) 为 400.55 ✓)
5. `HATCH pattern = ANSI31, solid = 0` ✓(图案为线型填充而非实体填充)

**本课无尺寸标注实体**,无标注回读值。

## ⚠ 数值出处核对 —— 关键发现

### 发现 1(重要):命令行里**唯一一个真实尺寸 10000 被脚本丢弃**

509.3–526.1s 讲师用 `PLINE` **连输三次 `10000`**(`<正交 开> 10000`)画出那条
供 `WIPEOUT _P` 使用的闭合矩形多段线 —— 这是本课**唯一一个 C 级长度**。

**但 `l20.scr` 把它写成了 `_.PLINE 0,-1000 1000,-1000 1000,-300 0,-300 _C`,
即 1000 × 700,与视频的 10000 × 10000 既不同尺寸、也不同形状(视频是正方形)。**

`l20.scr` 的头注写着「517-525s PLINE 正交开 边长 10000 x3 -> 闭合矩形多段线」,
说明**作者读到了这条证据却没有用**。这是本课最明确的一处「有出处却未采用」。

**建议**:把两条 `_.PLINE` 改成边长 10000 的正方形,即可把这两个实体提到 C 级。
(本次未改脚本。)

### 发现 2:全部几何尺寸无出处

除侧面数 6/36/60 外,`l20.scr` 里的**每一个坐标和尺寸都找不到证据出处**:

```
三个点方式覆盖区的 10 个顶点
圆 r=400            圆弧 (2800,-600)(3200,-300)(3600,-600)
椭圆 600 × 250      正多边形半径 400 ×3
大矩形 2400 × 1200  两个矩形多段线 1000 × 700
```

- `out/replica/l20/` 下**没有任何测量产物**(无 `geo.json`、无 `geo_overlay.png`、无 `build.py`);
- 命令行里这些数字一个都没出现过;
- 数值全是 100 的整数倍,呈明显的"排版取整"特征。

**判断:属于「演示布局(L)」而非「伪造关键参数」** ——
本课要证明的是 WIPEOUT 的**行为**(覆盖谁、边框显不显示、删不删源多段线),
这些都由 DXF 的实体计数与顶点表硬性验证了(见「验证」第 2、3、4 条),
**与靶子的绝对尺寸无关**。但按 SOP 铁律 R4,它们仍应记为**不可追溯**。

### 发现 3:`-HATCH` 的三个参数无出处

`_.-HATCH _P **ANSI31** **40** **0** 1200,-2400` 中:

- `ANSI31` 是 AutoCAD 的**默认图案**,可视为合理默认,但视频里讲师是在
  **对话框/功能区**里挑的图案,命令行**没有任何回显**,且他每次都 `*取消*` 了;
- **比例 `40`** —— **完全无出处**,是配合 2400×1200 矩形凑的视觉密度;
- 角度 `0` 是默认值。

本课视频里 `HATCH` 从头到尾**一次都没有落地**(767.5–784.3s 全部 `*取消*`),
严格说**这条 `-HATCH` 本不该进入执行序列**;它存在的唯一作用是给
`_.DRAWORDER … _F` 和最后那个 `_.WIPEOUT` 提供一个"被覆盖对象"。

**建议**:要么删掉这条填充(改用别的实体做 DRAWORDER 的靶子),
要么在脚本头注写明「填充为演示 DRAWORDER 而补,视频中该命令全部取消」。

### 发现 4:头注声称的覆盖率与本次复核不一致

`l20.scr` 头注写「证据: cmdmont m00-m14,m16,m18,m20-m22 (19/23)」。
本次独立复核只读了其中 14 张;**`_.DRAWORDER … _F` 的 `F` 选项**
恰好落在**未复核的 m20**(825–853s)。
本文档只能确认 `A`(192.0s)、`U`(823.7s)、`B`(867.8s)三个选项与
176.2s 的选项全集 `[对象上(A)/对象下(U)/最前(F)/最后(B)]`;
**`F` 被单独使用这一点未经本次验证**(但它在选项全集里,证据等级不低于 C−)。

## 做不到的部分

1. **全部几何尺寸不可追溯**(发现 2、3),本文档不为它们背书。
2. **视频里唯一的 C 级长度 10000 未被脚本采用**(发现 1)。
3. **`WIPEOUT` 的视觉效果无法在无头环境验证** ——
   区域覆盖的本质是"遮住下层图形",`accoreconsole` 没有显示,
   边框 ON/OFF/D 三种模式的差异只能靠 DXF 里 WIPEOUT 实体的边框标志间接体现,
   **拿不到"看上去被遮住了"这一级的证明**。
4. **`DRAWORDER` 的排序结果同样不可视验证** ——
   只能确认命令执行成功、实体仍在,无法确认叠放次序是否与视频一致。
5. **`HATCH` 的图案/比例/角度是对话框操作,命令行零回显** ——
   视频里的图案设置无法读出(讲师每次都取消了),脚本用的是自选值。
6. 讲师全程鼠标拾取,命令行不回显任何坐标 ——
   本课在原理上**只能拿到"选项级"的 C 级证据,拿不到"尺寸级"的**。
