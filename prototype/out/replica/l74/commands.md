## 四、构造方式

样板课,成品的价值在**文字样式表**;脚本用 8 条 `TEXT` 把每个样式**各写一行样张**,
好让样式在 DWG 里落地并可目视核对:

```
0,60  1.黑体-1.5  → "黑体1.5"      60,60  4.宋体-1.5 → "宋体1.5"     130,60  7.英文-1.5 → "windows"
0,50  2.黑体-2.5  → "黑体2.5"      60,50  5.宋体-2.5 → "宋体2.5"     130,50  8.英文2.5  → "windows"
0,35  3.黑体-5    → "黑体5"        60,35  6.宋体-5   → "宋体5"
```

样张的**文字内容和摆放位置是脚本自定的**(视频里的 MTEXT 全部被取消,见缺口 1)。

## 五、验证(verify.json 回读)

TEXT 8

## 七、做不到的部分 / 数值找不到出处

1. **视频里没有留下任何一段文字。** 两次 `MTEXT`(203.1s / 704.9s)都在
   「指定对角点」阶段 `*取消*`,`MTEDIT` 走的是就地编辑器(不回显)。
   所以脚本那 8 条样张的**内容("黑体1.5"…"windows")和位置全是编的**,
   只是为了让样式可见,属于主动偏离,在此明确记录。
2. **⚠ 8 个样式里有 5 个的名字和字高没有直接出处**(`2.黑体-2.5` / `3.黑体-5` /
   `4.宋体-1.5` / `6.宋体-5` / `8.英文2.5`)。它们是从两个 C 级样本
   (`1.黑体-1.5`、`7.英文-1.5`)+ 一个跨课样本(`5.宋体-2.5`)推出的命名规律外推的。
   规律很硬(序号连续、字高梯度一致),但**外推终究不是回读**。
3. **⚠ `8.英文2.5` 少了一个连字符。** 其余七个都是 `序号.族-字高`,
   只有第 8 个写成 `8.英文2.5`。既然它本身就是外推值,这个不一致很可能是笔误,
   建议统一成 `8.英文-2.5`。
4. **宽度因子(0.85 / 1.0)和倾斜角(0)没有出处。** 文字样式对话框里这两栏
   在读到的条带里从未清晰可见。
5. **注释性设置存在冲突。** 本课 203.1s / 704.9s 两次回显都是 `注释性: 否`,
   脚本据此建成非注释性样式;但课时83 的 MTEXT 回显是 `5.宋体-2.5(带注释性)`。
   说明**样式在后续课程里被改成注释性了**,或两者指的不是同一时刻的状态。本课按 `否` 落地。
6. **`DSETTINGS`(94.1–171.9s 反复打开)改了什么无证据**,脚本不设。
7. **另存样板的最终格式/路径无回显**(882.0s 只看到类型下拉),按流水线约定存 DWG+DXF。
