### 第 3 段 —— 合并后建面域再分解(y ≈ −2000,x ≈ 4500)

## 验证(verify.json)

```
l35.dxf  counts = { LINE: 202, CIRCLE: 1, ARC: 1, ELLIPSE: 1, SPLINE: 1,
                    LWPOLYLINE: 3, XLINE: 1 }
CIRCLE  = c(2100,150) r 200
ARC     = c(2900,0) r 300, 0°→180°
```

**五条自校验,全部通过:**

**1. 「不能分解」的四类对象**在 DXF 里**原封不动地存在**:
`CIRCLE: 1`、`ARC: 1`、`ELLIPSE: 1`、`SPLINE: 1` ——
四条 `_.EXPLODE _L` 全部无效,与视频的
`1 个不能分解。`(圆 / 圆弧)、`无法分解 ELLIPSE`、SPLINE 不可分解**逐条对应** ✓

**2. 「可以分解」的对象在 DXF 里全部不见了**:
`_.PLINE`(3 段)、`_.RECTANG`(4 边)、`_.WIPEOUT`、`_.-HATCH`、面域 ——
它们都被 `_.EXPLODE _L` 拆成了直线,所以 `LWPOLYLINE` 只剩 **3** 个
(= 三次 `PEDIT _M _J` 合并出来的三条多段线)✓

**3. `LINE: 202` 这个大数正是填充被分解的铁证**
`ANSI31` 是 45° 平行斜线图案,比例 40,填在 800 × 500 的矩形里;
`_.EXPLODE _L` 把它拆成了**上百条独立直线**。
若填充没有被成功分解,`LINE` 只会是十几条 —— **202 这个数量本身就证明了
「填充可以分解」(视频 262.6s)** ✓

**4. `LWPOLYLINE: 3`** = 三次合并的结果
(4 条直线 → 1 条、直线+圆弧 → 1 条、5 条直线 → 1 条闭合),
与视频 483.5s / 530.1s / 607.9s 的三条回显**一一对应** ✓
**注意最后那条闭合多段线在 `_.REGION` 后又被 `_.EXPLODE _L` 拆回直线**,
所以第 3 段留下的是直线而非多段线 —— 与 578s 的 `X EXPLODE 找到 1 个` 一致 ✓

**5. `XLINE: 1`** —— 构造线原样保留(未做分解演示)✓

**本课无尺寸标注实体**,无标注回读值。

## ⚠ 数值出处核对 —— 关键发现

### 发现 1:**本课命令行里一个几何数值都没有**

逐张核对 9 张蒙太奇后确认:
`CIRCLE 指定圆的半径或 [直径(D)]:`(139.2s)**连默认值 `<…>` 都没有回显**;
`RECTANG` / `LINE` / `PLINE` / `ARC` / `ELLIPSE` 全程鼠标拾取,**没有一次键入尺寸**。

**唯一带数字的回显全部是"对象计数"**:
`找到 1 个`、`找到 2 / 4 / 5 个`、`3 个对象已转换为…`、`已提取 1 个环`。
—— 而**本课要证明的恰恰就是这些计数**,它们全部是 C 级,并被 DXF 的实体数硬性复验。

### 发现 2:全部几何尺寸无出处(但不承载知识点)

```
直线长 600 / 400 / 300;多段线顶点 (800,0)(1100,300)(1400,0)(1700,300)
圆 r=200;圆弧三点;椭圆 800 × 300;矩形 600×400 / 800×500 / 600×600
样条四点;区域覆盖 800×500;各靶子的摆位(x 每 500~800 一排)
```

`out/replica/l35/` 下**没有任何测量产物**(无 `geo.json` / `geo_overlay.png` / `build.py`),
数值全是 100 的整数倍,呈"排版取整"特征。

**影响评估:低。** 本课的结论是「**哪些对象能分解、哪些不能;哪些线能合并、哪些不能**」,
这些结论**与靶子的尺寸完全无关**,并且已由 `verify.json` 的实体清单逐条证明。

**唯一有实质要求的一处**:第 2 段 JOIN 失败演示的两条直线
`(0,-2000)-(400,-2000)` 与 `(600,-2200)-(1000,-2200)`
**必须既不共线也不相接**,才能复现 403.3s 的
`已合并 0 个对象，操作中放弃了 2 个对象` —— 脚本满足这个条件(y 差 200、x 断开 200)✓

### 发现 3:`-HATCH` 的三个参数无出处

`_.-HATCH _P **ANSI31** **40** **0** 400,-950`:
- `ANSI31` 是 AutoCAD 默认图案,视频里讲师是在**对话框**里挑的,命令行零回显;
- **比例 `40` 完全无出处**;
- 角度 `0` 是默认值。

**影响:中。** `LINE: 202` 这个验证数字**直接取决于填充比例** ——
比例改成 20 或 80,分解出来的直线条数就完全不同。
因此「202」这个数只能证明"填充确实被分解了",**不能与视频做数量比对**。
