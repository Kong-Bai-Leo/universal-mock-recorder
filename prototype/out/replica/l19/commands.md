## 剔除(视频里出现但不进入执行序列)

- **撤销**:134.4–140.2s 的 `MOVE 找到 1 个` 连续三次 `_u MOVE`(**明确的撤销**),
  以及 138.2s 的 `*取消*` —— 面域位置最终没有移动,故脚本不含 MOVE。
- **失败演示**(记录但不执行):
  - 41.8–49.0s `REGION 找到 0 个` / **`未找到对象。`**;
  - 91.2–114.7s **`所有打开的边不能共面。`** `已提取 0 个环。已创建 0 个面域。`
    —— 脚本**保留了这个失败**:第一条 `_.REGION` 拾取的是圆弧上的点
    (`33186.080,21222.848`,到弧心距离 8337.0046 = 弧半径,精确落在弧上),
    开放圆弧无法成域,回放日志同样输出 0 个面域,**与视频一致**。
- **视图 / 视觉样式命令**(`-VIEW _swiso/_top`、`VSCURRENT _r/_2d`):
  是显示状态,不产生实体;无头环境无显示,**不纳入脚本**。
- **`VSCURRENT` 对话框取消**:248.2–262.6s、302.9–317.3s。
- **`*取消*`**:27.4(×2)、49.0、50.4、73.0、76.3、78.2、82.1、82.6、84.5、88.8、

## 验证(verify.json)

```
l19.dxf  counts = { LWPOLYLINE: 1, LINE: 1, ARC: 1, REGION: 2, 3DSOLID: 2 }
ARC  = c(31388.726, 13081.892) r 8337.0046, 16.4° → 138.7°
LINE = (3434.938, 21554.399) - (13364.868, 19899.410)
LWPOLYLINE = 正六边形 6 顶点,闭合
```

**逐项自校验**:

1. **`ARC` 包含角 = 138.7 − 16.4 = 122.3°** —— 与脚本 `_A 122.3` **逐位一致** ✓
2. **`ARC` 半径 8337.0046** = `|(39386.531,15435.774) − (31388.726,13081.892)|` ✓(解析式自洽)
3. **`REGION: 2` 而不是 4** —— 4 条 `_.REGION` 中:
   - 第 1 条拾取圆弧(开放曲线)→ **0 个面域**(复现视频 91.2s 的失败)
   - 第 2、3 条(三角形、矩形)→ 2 个面域,**留在图里**
   - 第 4 条(圆)→ 1 个面域,随后被 `_.EXTRUDE` **消耗成实体**
4. **`3DSOLID: 2`** = 圆面域拉伸 11495.1830 + 椭圆拉伸 7622.7958 ✓
5. **`LWPOLYLINE: 1`** —— 三角形与矩形都已转成 REGION,只剩正六边形 ✓
   六边形顶点表证明 `_I`(内接)生效:6 个顶点全部落在半径 1544.25 的圆上。
6. `_.REGION` 的每个拾取点都**精确落在实体边上**(SOP 坑表要求):
   `3635.422,9362.017` 是三角形一边的中点、`12514.861,8493.376` 在矩形底边、
   `20879.550,11324.502` = 圆心 x + 半径,在圆周上、`33186.080,21222.848` 在圆弧上。

**本课无尺寸标注实体**,无标注回读值。

## ⚠ 数值出处核对 —— 关键发现

### 结论:**没有发现凭空编造的数值**,但比例尺换算**不可精确复算**

- 两个拉伸高度 `11495.1830` / `7622.7958` 在命令行里**逐位存在**,是本课最硬的证据;
- 侧面数 `6`、`_I`、`_C` 均有命令行出处;
- 全部平面坐标都能在 `g_shapes.json` / `geo.json` 里找到**对应的测量记录**
  (上表已逐条对上),不是拍脑袋的数字。

**但是**:从像素到世界坐标的**换算式没有随交付物留档**,本次按各图形反算出的比例尺
并不完全一致 ——

| 图形 | 反算比例(单位/像素) |
|---|---|
| 矩形宽 4311.032 / 44 px | **97.98** |
| 矩形高 4632.751 / 47 px | **98.57** |
| 三角形 bbox 3667.6 / 37 px | **99.12** |
| 圆 2187.6878 / 21.9 px | **99.89** |
| 椭圆半短轴 1110.895 / 11.1 px | **100.08** |
| 六边形外接 1544.25 / 15.2 px | **101.60** |
| 椭圆半长轴 3854.8 / 37.9 px | **101.71** |

**离散度约 ±2%**,与像素量化误差(±0.5 px 在 15–45 px 尺度上就是 1–3%)同量级,
所以**这是正常的逐图形独立测量**,而不是编造;
但它意味着**无法给出一条统一的仿射变换把 `g_shapes.json` 复算成 `l19.scr`** ——
这一点与课时16(能给出精确变换式)不同,是本课证据链上唯一的薄弱环节。

**另外两个未留档的推导**:
- `122.3°`(弧包含角)—— 只能对应 `g_shapes` id 3 的轮廓,**没有留下角度测量记录**;
  好在它被 DXF 的 `16.4° → 138.7°` 自校验(差值恰为 122.3),内部自洽。
- 世界坐标的平移量(x 约 −17100、y 的翻转基准)—— **未留档**,属布局(L)。

**建议(本次未改脚本)**:补一个 `gen.py`,把「像素 → 世界」的比例与平移写死并留档,
即可把本课从"可对应"提升到"可复算"。

## 做不到的部分

1. **像素 → 世界的换算式无法精确复算**(见上),只能证明"每个数值都有对应的测量记录",
   不能证明"每个数值可由测量记录唯一算出"。
2. **讲师全程徒手画图,没有输入任何坐标或尺寸** ——
   除两个拉伸高度外,本课在原理上**拿不到任何 C 级平面几何证据**,最高只能是 M 级。
3. **视图 / 视觉样式(`-VIEW _swiso/_top`、`VSCURRENT _r/_2d`)无法在无头环境体现** ——
   `accoreconsole` 无显示,这些命令只改显示状态、不产生实体,已剔除并在此说明。
4. **134.4–140.2s 的 MOVE 被讲师自己 `_u` 撤销了三次**,最终位置未变,故不复现。
5. 视频 91.2s 的失败演示脚本里**保留**(第一条 `_.REGION` 打在圆弧上),
   但无头日志只会打印 `已创建 0 个面域。`,**无法复现视频里的红圈标注**。
