## 构造(每个实体怎么来的)

### DONUT —— **三组内外径全部 C 级**

| 脚本 | 内径 / 外径 | 出处 | 个数 |
|---|---|---|---|
| `_.DONUT **1000 1500** 0,0 3000,0 6000,0 9000,0 12000,0` | 1000 / 1500 | 137.8s `<1000.0000>`;145.9s `<1500.0000>` | 5 |
| `_.DONUT **0 1500** 0,-4000 3000,-4000` | 0 / 1500 | 145.9s `指定第二点: 0`;212.2s 默认变 `<0.0000>` 反证 | 2 |
| `_.DONUT **1000 1** 8000,-4000` | 1000 / 1 | 245.8s `<1.0000>: 1000`;`<1000.0000>: 1` | 1 |

**圆环中心点**(`0,0`、`3000,0`、…)是**布局(L)** —— 讲师全用鼠标点,命令行无坐标。

### REVCLOUD —— **弧长与样式全部 C 级,被套的图形是布局**

| 脚本 | 关键参数 | 出处 |
|---|---|---|
| `_.REVCLOUD **_A 1389.9662 2779.9325** _O 8000,-12000 _N` | 弧长 1389.9662 / 2779.9325 | **324.0s 状态行** |
| `_.REVCLOUD _O 34000,-12000 _N`(套五边形多段线) | 沿用上一组弧长 | 同上 |
| `_.REVCLOUD **_A 6666.6667 13333.3333** _O 58000,-40000 _N` | 弧长 6666.6667 / 13333.3333 | **489.1s 状态行**<br>(且 = 468.0s 输入的 10000 × 2/3 与 4/3,**自洽**) |
| `_.REVCLOUD **_S _C** _O 190000,-40000 _N` | 样式 = 手绘 | **532.8s `<普通>: c` → `手绘`** |
| `_.REVCLOUD **_S _N** _O 190000,-120000 _N` | 样式 = 普通 | **554.4s `<手绘>: N` → `普通`** |

**被套的图形**(3 个矩形 20000×12000 / 120000×70000 ×2、1 条五边形多段线)
与 4 个 `_.ZOOM _W` 窗口 —— **全部是布局(L)**,尺寸为排版取整。

> **为什么用 `_O`(对象)而不是 `_R`(矩形)/ `_F`(徒手画)?**
> SOP 坑表明确写着:「`REVCLOUD` 缺矩形/多边形/徒手画选项 —— 无头版只有
> [起点/弧长(A)/对象(O)/样式(S)];用 `RECTANG`/`PLINE` + `REVCLOUD _O` 等价实现」。
> 因此脚本先画 `RECTANG` / `PLINE`,再用 `_O` 把它转成云线 ——
> **这是无头环境下的等价实现,不是偷懒**。

## 验证(verify.json)

```
l22.dxf  counts = { LWPOLYLINE: 13 }
```

**实体数自校验(本课最漂亮的一条)**:

脚本一共画了 **8 个圆环 + 3 个矩形 + 1 条五边形多段线 + 5 条修订云线**,
表面上是 17 个多段线,DXF 里却**正好 13 个** ——
因为 `REVCLOUD _O` 会**把源多段线就地转换成云线**(不新增实体),
4 个被套的图形(3 矩形 + 1 五边形)+ 1 个直接画的云线 = 5 条云线,
`8 + 5 = 13` ✓ **命令语义被实体计数硬性证明**。

**圆环内外径的硬校验(从 DXF 顶点直接反算)**:

AutoCAD 的 DONUT 是一条「两顶点 + 半圆凸度」的闭合多段线,
两顶点间距 = **(内径 + 外径) / 2**,即中心线直径:

| DXF 顶点对 | 间距 | 反算 (内径+外径)/2 | 脚本值 | 结论 |
|---|---|---|---|---|
| `(−625, 0)` / `(625, 0)` 等 5 组 | 1250 | (1000+1500)/2 = **1250** | 1000 / 1500 | ✓ |
| `(−375, −4000)` / `(375, −4000)` 等 2 组 | 750 | (0+1500)/2 = **750** | 0 / 1500 | ✓ |
| `(7749.75, −4000)` / `(8250.25, −4000)` | 500.5 | (1000+1)/2 = **500.5** | 1000 / 1 | ✓ |

**三组内外径逐位对上**,而这三组数值全部有命令行出处 —— 证据链闭合。

**云线弧数**:5 条云线的顶点数为 31 / 32 / 39 / 39 / 39;
第 1 条套在周长 64000 的矩形上,平均弧长 64000/31 ≈ **2064**,
落在 `[1389.9662, 2779.9325]` 区间内 ✓;
第 3–5 条套在周长 380000 的矩形上,平均弧长 380000/39 ≈ **9744**,
落在 `[6666.6667, 13333.3333]` 区间内 ✓ —— **弧长参数确实生效了**。

**本课无尺寸标注实体**,无标注回读值。

## ⚠ 数值出处核对 —— 关键发现

### 结论:**没有发现编造的数值**;所有"承载课程知识点"的参数都是 C 级

`l22.scr` 里的数值可以干净地分成两类:

1. **知识点参数(内径/外径/弧长/样式)—— 6 个数值全部 C 级,逐位对得上**,
   而且被 DXF 顶点反算**二次证明**(见验证一节);
2. **摆放参数(圆环中心、矩形尺寸、ZOOM 窗口)—— 全部 L 级,无出处**。

第 2 类在本课**不承载任何证据**:云线套在多大的矩形上不影响 REVCLOUD 的语义,
弧数是否落在弧长区间内才是要证明的东西(已证明)。

## 做不到的部分

1. **矩形 / 五边形 / 圆环中心的尺寸与位置无出处**(L 级),本文档不为它们背书;
   讲师全程鼠标拾取,命令行不回显坐标,**原理上拿不到 C 级**。
2. **`REVCLOUD` 的矩形(R)/多边形(P)/徒手画(F)/修改(M) 四种方式无法在无头环境直接使用** ——
   SOP 坑表已记明无头版只保留 [起点/弧长(A)/对象(O)/样式(S)];
   脚本用 `RECTANG`/`PLINE` + `_O` 等价实现,**几何结果一致,但命令路径与视频不同**。
3. **「手绘(C)」样式的视觉差异无法验证** —— 无头环境无显示,
   只能确认命令接受了 `_S _C` 且实体仍生成,**看不出弧线是否真的呈手绘抖动**。
4. **`修改(M)` 方式(556.3s)未复现** —— 它要求在已有云线上点两个位置来替换一段,
   点位只有鼠标轨迹、无坐标回显,复现出来会是编造的点位,故不做。
5. **`PEDIT _R`(反转)与夹点拉伸未复现** —— 视频里都以 `*取消*` 结束。
