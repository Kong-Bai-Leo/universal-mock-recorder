## ⚠ 数值找不到出处 / 需要标注的问题

1. **字体 `simhei.ttf`**:命令流与画面里出现过的字体只有 `Century / Comic Sans MS / Yu Gothic / symap.shx /
   simplex.shx / 宋体 / 微软雅黑 / 微软雅黑 Light`(576–605s、887.0s 两处下拉框),脚本头注称 890s 对话框
   回读为「新宋体」。**`simhei` 在任何一处证据里都没有出现**。它是为让中文落进 DXF 而选的复现手段,
   不是课程内容 —— 已在此写明,不应被当作课程数值。
2. **890s 文字样式对话框回读**(字体名 新宋体 / 高度 0.0000 / 宽度因子 1.0000 / 倾斜角度 0):
   蒙太奇最后一帧止于 **887.5s**,该回读**不在蒙太奇里**,只能来自另抽的帧。本次核对**无法从命令流复核**,
   等级降为 D 且标"未复核"。宽度因子 1 / 倾斜 0 恰好也是 AutoCAD 默认值,即使读错也不改变结果。
3. **`30,35` 这个拾取点**:视频里"匹配对象"匹配到的是一条 **h=2.5** 的文字(546.2s),
   而脚本中 `30,35` 落在已被放大到 **10.5853** 的那条文字上,**复现结果的高度与视频相反**。
   这不是编造数值,但是**语义偏差**;verify.json 不回读文字高度,该偏差目前无人发现。建议:
   把拾取点改到 `(1, 26)`(命中 `阿萨斯`,h=2.5)才与 546.2s 的 `高度=2.5` 一致。
4. **插入点坐标全部是 L 级**,不代表原图坐标。

## 验证(verify.json)

```
counts: { TEXT: 5 }
TEXT: "银色坷垃"@(0,30) / "阿萨斯"@(0,25) / "银色s银色"@(20,15) / "lk银色jsfkl银色"@(20,30) / "银色sf银色f"@(20,5)
```
- 实体类型/数量与本课"只画单行文字再编辑"的性质一致。
- **验证盲区**:verify.json 未回读 `height` 与 `justify`,而本课的核心结论(10.5853、左对齐)恰恰落在这两项上。
  建议后续在 verify 里加 DXF 组码 40(高度)与 72/73(对正)的回读。

## 证据等级分布

- **C**:2.5000 / 10.5853 / 旋转 0 / JUSTIFYTEXT=L / 基点 E,M / `找到 1 个` / `1 个对象已更改` / `1 个非注释性对象已忽略`
- **D**:文字内容字符串、文字样式对话框的宽度因子 1.0 与倾斜 0(未复核)
- **L**:全部插入点、`30,35` 拾取点
- **M**:无(本课未用像素测量)

## 做不到的部分

- `FIND`(306–383s)是对话框内的查找替换,无命令行数值、无几何后果,不复现。
- `TEXTALIGN`(292.8s)当场取消,无终态,不复现。
- 注释性样式 `Annotative`(807–850s)只是演示"图纸高度"提示的变化,未产生保留实体,不复现。
- 文字**内容**与**插入点**无法升到 C 级。
