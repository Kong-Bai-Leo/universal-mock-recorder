## ⚠ 数值出处核对 —— 关键发现

### 发现 1(严重):**`l37.scr` 里根本没有 `ALIGN` 命令 —— 本课的主题命令完全没有复现**

`l37.scr` 的全部内容是:

```
FILEDIA 0 / OSMODE 0
_.LINE ×16
_.ELLIPSE ×1
_.ZOOM _E / _.SAVEAS / _.DXFOUT
```

**没有 `_.ALIGN`,没有任何编辑命令。**

也就是说,脚本**只复现了"对齐之后的终态几何",没有复现"对齐这个过程"** ——
这**直接违反 SOP 铁律 R2「复现的是过程:命令、顺序、参数都要来自视频证据」**。

**后果**:
- `verify.json` 只能证明 17 个实体的坐标与 `geo.json` 一致,
  **完全无法证明 `ALIGN` 命令被正确使用过**;
- 视频里最有价值的三条 C 级证据 ——
  `是否基于对齐点缩放对象？… : **Y**`(173.8s / 349.4s)、
  三点对齐链(249–264s)、`三个目标点共线。`(368.2s)——
  **一条都没有落进成品**。

**建议(本次未改脚本,按任务要求先报告)**:
在 16 条直线之外,另画一组"未对齐"的靶子(直线/矩形),
再补一条完整的 `_.ALIGN`,把三对源点/目标点用**已测得的线段端点**给出,
并对 `是否基于对齐点缩放对象？` 答 `_Y` —— 这样才能:
1. 复现视频的命令流;
2. 用"对齐后的坐标是否等于计算值"做硬验证(与课时23/24 的做法一致)。

### 发现 2:**本课命令行里一个几何数值都没有**

逐张核对 5 张蒙太奇后确认:
`ALIGN` 全程只有提示文本与 `Y/N` 应答;
`CIRCLE 指定圆的半径 <207.9825>`(189.6s)是**上一张图的残留默认值**、随即被 `*取消*`;
动态输入框里的 `194395.6083 < 259°`(69.1s)是**图纸绝对坐标**(10⁵ 量级),与本课几何无关。

**因此本课的几何在原理上只能做到 M 级** —— 而 M 级这一块**做得是合格的**:
`geo.json` 留档、变换式 `(px, 908 − py)` 无缩放、
16 条线 + 1 个椭圆**逐一对得上**、本次抽样 7 个实体复算全部通过。

### 发现 3:没有发现"编造的数值"

`l37.scr` 里的每一个坐标都能在 `geo.json` 里找到对应记录并复算,
**包括椭圆那三个带小数的参数**(`474.925 / 509.958`、`436.875 / 471.642`、`17.800`)——
它们是由 `geo.json` 的 `c / a / b / rot` 四个字段**解析算出来的轴端点**,不是猜的:

```
中心 (455.9, 908−417.2=490.8);半长轴 27.0;倾角 45.2°(= 180 − 134.8)
轴端点 = 中心 ± 27.0 × (cos45.2°, sin45.2°) = (474.925, 509.958) / (436.875, 471.642) ✓
半短轴 = 17.8 ✓
```

## 做不到的部分

1. **`ALIGN` 命令本身未复现**(发现 1)—— 这是本课最大的缺口,
   成品 DWG 无法证明对齐工具被使用过。
2. **本课拿不到任何 C 级几何证据**(发现 2),全部坐标最高 M 级。
3. **讲师的源点/目标点全部是鼠标拾取**,命令行不回显坐标 ——
   即使补上 `_.ALIGN`,那三对点也只能用**测量到的线段端点**代替,
   仍然是 M 级,而不是视频里的真实点位。
4. **`三个目标点共线。` 失败回显未复现** —— 它只输出报错、不产生实体。
5. **`是否基于对齐点缩放对象？` 的 `Y`(缩放)与 `N`(不缩放)差异未体现** ——
   这是本课的核心知识点,却因为没有 `_.ALIGN` 而完全缺席。
