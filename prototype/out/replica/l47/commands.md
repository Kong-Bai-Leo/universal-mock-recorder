> 命令行只记录了进出编辑器和夹点拖框,**没有任何数值参数**。这是事实,不是漏读。

## 剔除

- 143.0–161.8s:13 次夹点 `** 拉伸 **`,终态被后续编辑覆盖,不入序列。
- 163.2s / 164.2s / 166.1s / 167.5s:窗选 `*取消*`。
- **900s 的「选择颜色 - 真彩色」对话框到 935s 终帧仍未按"确定"**,文字仍是白色 ——
  按 R3 剔除,脚本**不设文字颜色**。这一条是本课最容易被误抄成"文字为 RGB(16,62,112)"的陷阱。
- 530s 的字高 7.5 是中间态,900s 已改为 10,取终态。

## ⚠ 数值找不到出处

1. **框宽 60 / 45 / 70 / 190 与四个插入点**:命令行全程无 `宽度(W)` 分支、无坐标回显,
   画面上的框由 143–161s 的夹点拖出且无标注。这些是**布局值(L)**,不代表原图尺寸。
   其中 `_W 190` 是为容纳第 4 段很长的符号行而设,尤其应视为复现需要而非课程数值。
2. **字高 10 只有 D 级**(功能区读值),无命令行回显。
3. **900s 真彩色 RGB(16,62,112) 未被应用**,已按 R3 剔除;若任何下游文档把它写成成品颜色,
   那是错的。
4. **字体 `simhei.ttf`**:与 900s 功能区读到的「黑体」一致,**有 D 级出处**,可保留;
   但 530s 时是 `Microsoft YaHei UI`,取的是终态。

## 验证(verify.json)

```
counts: { MTEXT: 4 }
```
- 4 个 MTEXT 与 900s 终帧上的四段文字对应。
- **验证盲区**:verify.json 未回读正文字符串与字高。本课的核心结论(符号集、大小写转换、`九十`)
  全部落在正文字符串上,建议补 DXF 组码 1/3(MTEXT 文本)回读 —— 这是唯一能证明
  "符号确实落进 DWG"的手段(尤其 `®` / `í` / `¢` / `≈` 这些非 GB2312 字符很容易在编码环节丢失)。

## 证据等级分布

- **C**:无数值;仅 `_mtedit` / `** 拉伸 **` / `*取消*` 等过程证据
- **D**:字高 10、字体 黑体、正文内容与符号、右键菜单项、真彩色对话框数值(**未应用**)
- **L**:全部框宽与插入点
- **M**:无

## 做不到的部分

- 编辑器内的符号插入、查找替换、大小写转换**不进命令行**,永远是 D 级。
- **背景遮罩**在无头 `-MTEXT` 里无对应参数,未复现。
- 900s 的真彩色对话框未确认,不复现颜色。
- 143–161s 的夹点拖框无终态数值,不复现。
