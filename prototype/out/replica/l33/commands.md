## 构造

### A. 第一个演示 —— 矩形路径上的定距阵列

```
_.RECTANG 0,0 282000,133000        ← 路径(矩形)
_.CIRCLE 0,0 16508.7118            ← 阵列源对象
_.ARRAYPATH _L / (路径拾取 141000,0) / 83 / 10000 / _A / _N / _X
```

| 数值 | 出处 | 等级 |
|---|---|---|
| **圆半径 16508.7118** | **662.6s `指定圆的半径或 [直径(D)] <16508.7118>`** | **C** |
| **项目数 83** | **618.4s `最大项目数 = 83` / `指定项目数 … <83>:`** | **C** |
| **间距 10000** | **617.9s `指定沿路径的项目之间的距离 … : 10000`** | **C** |
| **对齐项目 = 否(`_A _N`)** | **641.5s `是否将阵列项目与路径对齐？… <是>: N`** | **C** |
| **`ARRAYASSOCIATIVITY 0`(非关联)** | SOP 坑表 +「`类型 = 路径 关联 = 是`」需改为非关联才能得到干净实体 | **C(依据)** |
| 矩形 282000 × 133000 | **周长 = 2 × (282000 + 133000) = 830000**,<br>`830000 ÷ 10000 = **83**` —— **与 618.4s 的「最大项目数 83」精确吻合**;<br>但**长宽比本身无出处**(见下) | **C(周长)/ L(长宽比)** |
| 路径拾取点 141000,0 | = 矩形底边中点,保证拾取落在实体上 | **L** |

### B. 第二个演示 —— 四段折线合并成一条多段线

```
_.LINE 0,-400000 110766.6,-492943.4          ┐
_.LINE 110766.6,-492943.4 221533.2,-400000   │ 四段 Z 字折线
_.LINE 221533.2,-400000 332299.8,-492943.4   │
_.LINE 332299.8,-492943.4 443066.4,-400000   ┘
_.PEDIT _M _W … / _Y / _J / 0 / _X           ← 合并
```

| 数值 | 出处 | 等级 |
|---|---|---|
| **合并 4 条 → 1 条多段线** | **694.8s `JOIN 找到 4 个` → `4 个对象已转换为 1 条多段线`** | **C** |
| 四段折线的坐标(110766.6、−492943.4 等) | **✗ 无出处**(见下) | **✗** |

> **为什么用 `PEDIT _M _J` 而不是 `JOIN`?**
> SOP 坑表:「`JOIN` 报错 —— 首问是**单选**源对象;改用 `PEDIT _M` + `_J`」。
> 视频里讲师用的是 `J`(JOIN),脚本用等价的 `PEDIT _M _J`,**结果相同**。

- `ARRAYASSOCIATIVITY 0` 生效(非关联阵列才会落成 83 个独立 `CIRCLE` 实体,

—— **间距 10000 被逐个圆心证明** ✓
且**沿矩形底边呈直线排布**,说明 `对齐项目 = 否`(`_A _N`)生效

## ⚠ 数值出处核对 —— 关键发现

### 发现 1(好的一面):第一个演示的**每一个数值都可追溯,并被 83 个实体硬性证明**

`16508.7118` / `10000` / `83` / `对齐=否` 四个值全部有逐字对得上的命令行出处,
而且 **`830000 ÷ 10000 = 83` 这条恒等式把"矩形周长"也锁死了** ——
换句话说,**矩形的周长不是随手取的**,它必须正好是 830000 才能复现视频里
618.4s 的那句「最大项目数 = 83」。脚本做到了。

### 发现 2:矩形的**长宽比**无出处

`282000 × 133000` 的周长确实是 830000(C 级约束),
但**满足周长 830000 的矩形有无穷多个**,`282000 : 133000` 这个比例
在命令行、标注、对话框里**都找不到出处**
(36.0–41.3s 讲师画矩形时命令行**没有任何尺寸回显**,随后就 `*取消*` 了)。

**影响:低。** 圆心间距、圆个数、半径都不受长宽比影响;
只有"圆分布在矩形四条边上的具体位置"会变。

### 发现 3:**四段折线的 8 个坐标完全无出处**

```
(0, -400000) (110766.6, -492943.4) (221533.2, -400000)
(332299.8, -492943.4) (443066.4, -400000)
```

- `out/replica/l33/` 下**没有任何测量产物**(无 `geo.json` / `geo_overlay.png` / `build.py`);
- 命令行里这些数字一个都没有出现过;
- 数值带 1 位小数、看似"算出来的",但**推不出算法**:
  单段长 `√(110766.6² + 92943.4²) = 144594.6`,总长 `578378`,
  与 `10000` / `83` / `830000` **都没有整数关系**;
- 这条折线在脚本里**只用于演示 `PEDIT _M _J` 合并**,没有做阵列。

**判断:属"演示靶子",不承载知识点,但按 SOP 铁律 R4 应记为无出处。**

**建议(本次未改脚本)**:折线可以改用有出处的尺寸(如每段水平投影 = 10000 的整数倍),
或者干脆用矩形边长构造,即可把无出处面积清零。

### 发现 4:视频里有一大堆被丢弃的半径默认回显

`1060.3868`(359.6s)、`73441.6469`(439.3s)、`138252.1792`(541.1s)、
`21490.5848`(603.5s)、`41434.9649`(671.7s)、`161.5082`(217.5s,课时32 残留)
—— 讲师换了 6 种圆大小,**脚本只取了最后落定的 `16508.7118`(662.6s)**。
这是**正确的取舍**(最后那次才是路径阵列真正用的源对象),此处记录以备核查。

## 做不到的部分

1. **四段折线的坐标、矩形的长宽比无出处**(发现 2、3),本文档不为它们背书。
2. **视频里的路径阵列是「关联阵列」,脚本落地的是「非关联」** ——
   `ARRAYASSOCIATIVITY 0` 使 83 个圆成为独立实体(便于验证),
   但**成品 DWG 里没有关联阵列对象**,`选择夹点以编辑阵列` 这条编辑链无法体现。
3. **`定数等分(D)` 方法未复现** —— 讲师看了对话框就选了 `定距等分(M)`。
4. **`切向(T)` / `z 方向(Z)` / `基点(B)` / `行(R)` / `层(L)` 五个子选项未复现** ——
   它们要么只在提示行出现、要么需要鼠标点向量端点(无坐标回显)。
5. **样条曲线作路径的演示未复现**(103.7–115.7s)——
   那条样条是徒手画的,顶点无出处;脚本改用有周长约束的矩形作路径。
6. **`JOIN` 命令本身未直接使用** —— SOP 坑表指明无头版 `JOIN` 首问是单选,
   脚本改用等价的 `PEDIT _M _J`;结果(1 条多段线)与视频一致,但命令名不同。
