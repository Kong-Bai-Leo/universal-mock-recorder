## 构造(每个图形怎么来的)

**没有任何一条落地线段来自命令行数值**。命令行里的 1000 / 2000 / 60 / 30 / −30 / 45
全部属于"输一次 → 立即 `*取消*`"的试画,终态画布上不存在。
终态画布上是讲师徒手连点画出的 26 条线段(三组:右上大折线、中部箭头/图形、左下小方框)。

构造方式:**像素测量**(`cv/measure.py` 输出 `end.json`,t=874.0s,`--color white`),
共检出 **26 条 lines**,再按 `--flipy 597` 直接 1:1 映射成图形单位:

```
end.json  p0=[598,178] p1=[912,178]  →  _.LINE 598.000,419.000 912.000,419.000
                                              (419 = 597 − 178)
```

`l5.scr` 里的 26 条 `_.LINE` 与 `end.json` 的 26 条一一对应,**没有第 27 条**,
即脚本中不存在测量之外凭空添加的线段。

## 验证(verify.json)

```
l5.dxf  counts = { LINE: 26 }
```

26 条 LINE 与 `end.json` 的 26 条测量线段逐条对得上,例如
`{p0:[598,419], p1:[912,419]}` ← `end.json {p0:[598,178], p1:[912,178]}`(flipy 597)。
本课**无标注实体**(视频里的 DIM 被取消),因此无标注回读值。

| 内容 | 等级 |

## 数值是否都能找到出处

**能。** `l5.scr` 中除固定头尾(`FILEDIA 0` / `OSMODE 0` / `ZOOM _E` / `SAVEAS` / `DXFOUT`)
外的全部 26 条 `_.LINE`,每一条的 4 个坐标都能在 `end.json` 里逐一对上,
**没有发现无出处(疑似编造)的数值**。

## 做不到的部分

1. **图形单位不是真实尺寸**:本课讲师全程徒手画,终态画布没有任何标注,
   无法把像素换算成毫米。脚本采用"1 像素 = 1 图形单位"的约定,
   只保证**形状与相对比例**忠实,不声称绝对尺寸等值。
2. 视频里输过的 1000/2000/60/45 等长度**无法落地**——它们对应的线段
   在视频里当场就被 `*取消*` 了,强行画上去反而是编造。
3. 733s 起的 `_dim` / `_dimangular` 只走到提示行就退出,没有可回读的标注文字。
