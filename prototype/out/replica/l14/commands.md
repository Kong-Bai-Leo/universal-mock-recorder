## 构造

`l14.scr` 造了 **3 个等大矩形 + 3 个用户定义填充**,一字排开:

| 图形 | 脚本 | 出处 |
|---|---|---|
| 矩形 ×3 | `_.RECTANG 0,0 140,100` / `160,0 300,100` / `320,0 460,100` | **L(布局)** |
| 填充 1 | `_.-HATCH _P **_U** 0 8 _N 70,50` | 角度 0、间距 8、单向 |
| 填充 2 | `_.-HATCH _P **_U** 45 8 _N 230,50` | 角度 45、间距 8、单向 |
| 填充 3 | `_.-HATCH _P **_U** 45 8 **_Y** 390,50` | 角度 45、间距 8、**双向(交叉)** |

`_U`(用户定义)这一选择**有 C 级出处**:873.6s 功能区宏回显 `_-hatchedit_p**USER**`。
角度 / 间距 / 双向三个参数的出处见下节。

填充前 `_.ZOOM _W -60,-60 520,160` 覆盖全部边界 —— 坑表要求,非证据。

## 验证(verify.json)

```
l14.dxf  counts = { LWPOLYLINE: 3, HATCH: 3 }
  LWPOLYLINE [0,0]-[140,0]-[140,100]-[0,100]        closed
  LWPOLYLINE [160,0]-[300,0]-[300,100]-[160,100]    closed
  LWPOLYLINE [320,0]-[460,0]-[460,100]-[320,100]    closed
  HATCH pattern="_U" solid=0   ×3
```
三个填充的 `pattern` 回读为 `_U`,证明**用户定义模式确实落地**;
三个边界闭合正确。本课无标注实体。

> 注:`verify.json` **不回读**填充的角度 / 间距 / 是否双向,
> 因此这三项**没有独立验证**。

## ⚠ 数值出处核对 —— 发现

### 发现 1:角度 / 间距 / 双向三项**找不到出处**
用户定义图案的三个关键参数在 AutoCAD 里只在**对话框**中输入,
命令行**一个字都不回显**(全课 15 张蒙太奇印证了这一点)。
`out/replica/l14/cv/slices/` 为空(probe 用了 `--no-slices`),
也没有对话框截图留档。因此:

- `0` / `45`(角度)—— **不可追溯**;
- `8`(间距)—— **不可追溯**;
- `_N` / `_N` / `_Y`(是否双向)—— **不可追溯**。

三者是本课的**核心教学内容**,却恰恰是唯一没有证据的部分。
需要补一次带 `slices` 的探测,或对 499–655s(HPDLGMODE=2 强制走对话框那一段)抽帧留档。

### 发现 2:图案名 HOUND / HONEY 有证据却没用上
855.8s / 860.6s 的功能区宏 `_-hatchedit_pHOUND` / `_-hatchedit_pHONEY`
是 C 级证据,说明讲师还演示了 **HOUND(犬牙)** 和 **HONEY(蜂窝)** 两个图案,
脚本里没有对应实体。

### 发现 3:边界坐标是布局值
`0,0 140,100` / `160,0 300,100` / `320,0 460,100` 三个矩形是为排版选的整数,
**命令行无出处,也没做像素测量**,属 L 级。视频里的边界是徒手画的不规则形。

### 发现 4:HPDLGMODE 未纳入脚本
499.7s / 640.8s 的 `HPDLGMODE 1→2→1` 是明确的 C 级系统变量演示,
脚本用的是 `-HATCH`(命令行版),等价但**没有把 HPDLGMODE 落到图纸**。
