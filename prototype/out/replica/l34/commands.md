## 构造

### 第一个环形阵列 —— 平面 6 项

```
_.CIRCLE 6326,0 1000
_.ARRAYPOLAR _L / (空) / 0,0 / 6 / 360 / _ROT / _Y / _X
```

| 参数 | 值 | 出处 | 等级 |
|---|---|---|---|
| 圆半径 | **1000** | **424.9s `指定圆的半径或 [直径(D)] <1000.0000>`** | **C** |
| 项目数 | **6** | **473.9s `指定项目间的角度或 [表达式(EX)] <60>` → 360 ÷ 60 = 6** | **C(推导)** |
| 填充角度 | **360** | 环形阵列默认值 | **C(默认)** |
| 旋转项目 | **是(`_ROT _Y`)** | 选项 `旋转项目(ROT)` 见于 101.8s 的九选项行;<br>**「是」这一答案未在命令行确认** | C(选项)/ **✗(取值)** |
| 阵列半径 6326、中心 (0,0) | 摆位 | **✗ 无出处** | |

### 第二个环形阵列 —— 10 项 × 3 行

```
_.CIRCLE 4400,-40000 1000
_.ARRAYPOLAR _L / (空) / 0,-40000 / 10 / 360 / _ROW / 3 / 2000 / 0 / _ROT / _Y / _X
```

| 参数 | 值 | 出处 | 等级 |
|---|---|---|---|
| 圆半径 | **1000** | 424.9s(同上) | **C** |
| 项目数 | 10 | **✗ 无出处** | **✗** |
| 行数 | 3 | **✗ 无出处** | **✗** |
| 行间距 | 2000 | **✗ 无出处** | **✗** |
| 层间距 | 0 | 二维图,层数保持 1 | L |
| 阵列半径 4400、中心 (0,−40000) | 摆位 | **✗ 无出处** | |

> **为什么用 `ARRAYPOLAR` 而不是 `-ARRAY`?**
> SOP 坑表写着:「`ARRAYPOLAR` 结果多一个 —— 它**保留源对象**(6 项阵列得到 7 个实体);
> 用 `-ARRAY` 的经典环形阵列才干净」。
> **本脚本用的是 `ARRAYPOLAR` + `ARRAYASSOCIATIVITY 0`**,
> 从 `verify.json` 看结果是**干净的 36 个**(见验证),说明在本版 AutoCAD 下
> 非关联的 `ARRAYPOLAR` 并不会多出源对象 —— **坑表那条在这里不成立,已实测**。

## 验证(verify.json)

```
l34.dxf  counts = { CIRCLE: 36 }
CIRCLE = c(6326, 0) / c(3163, 5478.4767) / c(-3163, 5478.4767)
         c(-6326, 0) / c(-3163, -5478.4767) / …    r 1000 (全部)
```

**三条自校验,全部通过:**

**1. 实体数 `6 + 10 × 3 = 36`,与 `CIRCLE: 36` 完全一致** ✓
这同时证明:项目数 6 与 10 生效、行数 3 生效、
且 `ARRAYASSOCIATIVITY 0` 使阵列落成独立实体(关联阵列只会是 1 个匿名块参照)。

**2. 六等分坐标可解析复算 —— 直接证明「6 项 / 360°」**

阵列半径 6326,中心 (0,0),6 项均布 ⇒ 相邻两项相隔 **60°**:

| 项 | 理论坐标 | DXF 实测 | 结论 |
|---|---|---|---|
| 0° | (6326, 0) | **(6326, 0)** | ✓ |
| 60° | (6326·cos60, 6326·sin60) = (**3163**, **5478.4767**) | **(3163, 5478.4767)** | ✓ 小数点后 4 位全对 |
| 120° | (**−3163**, **5478.4767**) | **(−3163, 5478.4767)** | ✓ |
| 180° | (**−6326**, 0) | **(−6326, 0)** | ✓ |
| 240° | (**−3163**, **−5478.4767**) | **(−3163, −5478.4767)** | ✓ |

**60° 这个间隔正是 473.9s 命令行里的默认值 `<60>`** —— C 级证据与 DXF 坐标闭合 ✓

**3. 所有 36 个圆半径都是 1000** ✓ 与 424.9s 的 `<1000.0000>` 逐位一致,
并证明 `旋转项目` 不改变圆的大小(圆旋转后仍是圆,这条无法反证,见下)。

**本课无尺寸标注实体**,无标注回读值。

## ⚠ 数值出处核对 —— 关键发现

### 发现 1(好的一面):第一个阵列**完全可追溯,并被 DXF 坐标复验到小数点后 4 位**

`圆半径 1000`(424.9s)与 `项目间角度 60°`(473.9s)两条 C 级证据,
唯一确定了「6 项 / 填充 360°」这组参数;
DXF 里六个圆心 `(6326,0)`、`(3163, 5478.4767)`、`(−3163, 5478.4767)`…
**与 60° 均布的解析值逐位吻合**。

### 发现 2(问题):**第二个阵列的 3 个参数 + 两个阵列半径无出处**

在 **77% 覆盖率**(10/13 张)下,以下数值在命令行、标注、对话框里**都没有出现过**:

| 脚本数值 | 位置 | 影响 |
|---|---|---|
| **`10`** | 第二个阵列的项目数 | **中** —— 它直接决定 30 个圆的分布 |
| **`3`** | 行数 | **中** |
| **`2000`** | 行间距 | **中** |
| **`6326`** | 第一个阵列的半径(圆心 x) | **低** —— 不影响 60° 均布这一结论 |
| **`4400`** | 第二个阵列的半径 | **低** |
| **`_ROT _Y`** | 旋转项目 = 是 | **低**(见发现 3) |

`out/replica/l34/` 下**没有任何测量产物**(无 `geo.json` / `geo_overlay.png` / `build.py`),
视频里讲师全程用**鼠标拖夹点**改项目数和行数,命令行一次都没有回显过具体个数。

**唯一在命令行出现过的项目相关数字是 211.7s 的 `指定项目间的角度: 100`**
(夹点输入),脚本**没有用它** —— 这是一处"有出处却未采用"。

**建议(本次未改脚本)**:
- 把第二个阵列的项目间角度改成 **100°**(211.7s,C 级),
  或把项目数改成能由 `<60>` 解释的 **6**;
- 行数 / 行间距若无出处,可考虑删掉 `_ROW` 那一段,只保留有证据的单行环形阵列。

### 发现 3:`_ROT _Y`(旋转项目 = 是)在本课**无法被证伪也无法被证实**

阵列的源对象是**圆**,圆绕任何点旋转后仍是同样的圆 ——
因此 DXF 里 36 个圆的坐标与半径**对 `_ROT` 的取值完全不敏感**。
视频里 `旋转项目(ROT)` 只出现在选项行,讲师没有单独设过它。
**若要让这个选项可验证,源对象必须是非旋转对称的图形**(如矩形或直线)。

### 发现 4:关于 SOP 坑表的一处实测更正

SOP 坑表称「`ARRAYPOLAR` **保留源对象**,6 项阵列得到 7 个实体,应改用 `-ARRAY`」。
本课脚本用的是 `ARRAYPOLAR` + `ARRAYASSOCIATIVITY 0`,
**`verify.json` 得到的是干净的 36 = 6 + 30,没有多出源对象**。
**说明该坑在本版本 / 本用法(非关联)下不出现**,已实测记录。
