## 构造(每个图形怎么来的)

`l18.scr` 的结构是「**一排演示靶子 + 对每个靶子做一次 DIVIDE/MEASURE**」。

### A. 系统变量(D 级,对话框读出)

| 变量 | 值 | 出处 |
|---|---|---|
| `PDSIZE` | **−5** | `f240.png` / `f850.png` 对话框 `点大小(S): 5.0000 %` + ⦿`相对于屏幕设置大小(R)`<br>(相对屏幕 ⇒ **负号**,5% ⇒ `−5`) |
| `PDMODE` | **34** | `f850.png` 对话框**第 2 行第 3 格**高亮(圆内加十字)<br>行号 → 32(带圆),列号 → 2(十字)⇒ `32 + 2 = 34` |

### B. 演示靶子(布局 L 级 —— **本课最大的证据缺口,见下节**)

| 靶子 | 脚本 | 作用 |
|---|---|---|
| 直线 1 | `_.LINE 0,900 1000,900` | **长 1000 有 C 级出处**(478.1s) |
| 圆 | `_.CIRCLE 300,400 200` | 圆的等分演示 |
| 圆弧 | `_.ARC 700,200 900,500 1100,200` | 圆弧的等分演示 |
| 矩形 | `_.RECTANG 1300,200 1900,600` | 矩形(闭合多段线)的等分演示 |
| 椭圆 | `_.ELLIPSE 2100,400 2700,400 150` | 椭圆的等分演示 |
| 多段线 | `_.PLINE 0,-200 300,0 600,-200 900,0` | 折线的等分演示 |
| 拟合多段线 | `_.PLINE 1300,-400 …` + `_.PEDIT 1300,-400 _S` | 651.4s `PEDIT → S` 的复现 |
| 样条 | `_.SPLINE 2400,-400 …` | 790.1s 样条的等分演示 |
| 直线 2 | `_.LINE 0,-800 1000,-800` | MEASURE 100 的靶子 |

## 验证(verify.json)

```
l18.dxf  counts = { LINE: 4, CIRCLE: 1, ARC: 1, LWPOLYLINE: 2, ELLIPSE: 1,
                    POLYLINE: 1, VERTEX: 22, SEQEND: 1, SPLINE: 2, POINT: 113 }
CIRCLE  = c(300,400) r 200
ARC     = c(900,283.3333) r 216.6667, 337.38°→202.62°
LINE    = (0,900)-(1000,900) / (0,-800)-(1000,-800)
          / (3400,-1000)-(3400,2600) / (4900,-1000)-(4900,2600)
LWPOLYLINE = 矩形 (1300,200)(1900,200)(1900,600)(1300,600) 闭合
             折线 (0,-200)(300,0)(600,-200)(900,0) 开放
ELLIPSE = c(2400,400) major(-300,0) ratio 0.5
```

**自校验(本课最强的一条)**:

1. **`LINE 3` 长度 = 2600 − (−1000) = 3600** —— 与 867.4s 命令行 `3600` **逐位一致** ✓
2. **偏移线落在 x = 4900 = 3400 + 1500** —— 与 871.7s `1500` **逐位一致** ✓
3. **`POINT` 共 113 个**,按靶子分组统计(从 DXF 直接聚类):
   - 直线 1 `DIVIDE 5` → **4 个**(开放对象 = n−1)✓
   - 圆 / 矩形 / 椭圆 `DIVIDE 10` → **各 10 个**(闭合对象 = n)✓
   - 圆弧 / 折线 `DIVIDE 10` → **各 9 个**(开放对象 = n−1)✓
   - 拟合多段线 `DIVIDE 20` → **19 个**(开放 = n−1)✓
   - 其余为 3 条 MEASURE 的落点。
   **「闭合得 n 点、开放得 n−1 点」这条 AutoCAD 规则被完整复现**,
   说明每条 DIVIDE 都确实选中了预期的那个实体(没有选错对象)。
4. `POLYLINE + VERTEX 22 + SEQEND` = `PEDIT _S` 生成的样条拟合多段线(651.4s)✓

**本课无尺寸标注实体**,无标注回读值;点样式以 `PDMODE/PDSIZE` 落进 DWG 头(可用 `f850.png` 目视比对)。

### 发现 1:11 个「演示靶子」的尺寸**没有任何证据出处**

以下数值在 `l18.scr` 里出现,但**在命令行、对话框、标注中都找不到出处**,
`out/replica/l18/` 目录下也**没有 `geo.json` / `geo_overlay.png` 等测量产物**:

```
圆    半径 200,圆心 (300,400)
圆弧  三点 (700,200) (900,500) (1100,200)
矩形  (1300,200)–(1900,600)  即 600 × 400
椭圆  轴端 (2100,400)–(2700,400)、半短轴 150   即 600 × 300
折线  (0,-200)(300,0)(600,-200)(900,0)
拟合多段线 (1300,-400)(1500,-100)(1700,-400)(1900,-100)(2100,-400)
样条 1 (2400,-400)(2600,-100)(2800,-400)(3000,-100)
样条 2 (1300,-900)(1500,-600)(1700,-900)(1900,-600)
```

**判断:这些属于"合理但不可追溯"的一类,不等同于编造关键参数,但按 SOP 铁律 R4
仍应标为无出处。** 理由与限度:

- 它们是**等分演示的靶子**,本课要证明的是「DIVIDE/MEASURE 在各类对象上的行为」,
  这一点由 POINT 计数规则(闭合 n / 开放 n−1)完整证明,**与靶子的绝对尺寸无关**;
- 但 **`MEASURE` 的落点数量确实依赖靶子长度** ——
  `_.MEASURE 1300,-900 100` 作用在样条 2 上,样条 2 的长度无出处,
  因此**这一条 MEASURE 得到 11 个点是不可追溯的**;
  相对地,`_.MEASURE 3400,-1000 300`(靶子长 3600,C 级)与
  `_.MEASURE 500,-800 100`(靶子长 1000,C 级)是**可追溯的**。
- 数值本身呈明显的「整百网格」特征(200/300/600/400/150),
  是**为排版方便取的整数**,而不是从画面量出来的 —— 这也是它们没有测量产物的原因。

**建议(本次未改脚本)**:补做 `measure.py` 对终态帧(如 `f905.png` / `f920.png` / `f926.png`)
取一次几何,把这 8 个靶子换成 M 级坐标并留档;或至少在脚本头注里写明
「靶子尺寸为任取的演示布局,不承载证据」。
