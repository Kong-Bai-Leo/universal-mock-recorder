## ⚠ 数值找不到出处(重点)

1. **`-MTEXT … _W 60` 与 `_W 80` 的框宽 60 / 80**:全课 MTEXT 的对角点**始终是鼠标拖拽**
   (527.7s `858.9044<254°`、528.2s `937.0754<231°` 是动态输入的显示值,且是极坐标长度不是框宽),
   `宽度(W)` 选项在 84.5s 的选项表里出现过但**从未被选用**,命令行**没有任何一次输出过框宽数值**。
   60 / 80 是为让两块文字排得开而定的**布局值(L)**,应如实标为 L 而非 C。
2. **字体 `simhei.ttf`**:视频 500.7s 的 `'_style` 下拉框高亮的是 **新宋体**;`simhei` 无出处,
   属于让中文落进 DXF 的复现手段。
3. **脚本头注称"380s 特性面板回读(对正 左上 / 高度 2.5 / 旋转 0 / 内容 …)"**:
   本次核对的 6 张蒙太奇里 **380s 附近没有对应条带**(m01 从 322.2s 跳到 340.9s 再到 399.0s),
   该回读只可能来自另抽的帧,**无法从命令流复核**。可复核的最接近证据是 **568.0s 的特性面板碎片**
   (`旋转 0`),等级 D。
4. **593–687s 的三次 SCALETEXT 未纳入脚本**:其中 687.1s 有明确的 `1 个对象已更改`,
   即视频里确实有一次生效的文字缩放,而成品 DWG 里没有对应体现。这是**已知的复现缺口**(见末节),
   不是编造,但要写明。

## 验证(verify.json)

```
counts: { MTEXT: 2 }
```
- 两个 MTEXT 与视频"演示两块多行文字(第二块用 H 改高为 10)"一致。
- **验证盲区**:verify.json 未回读 MTEXT 的 `height` / `width` / `attachment`,
  而本课唯一的 C 级数值(高度 10)恰恰落在 height 上。建议补 DXF 组码 40(字高)与 41(框宽)的回读。

## 证据等级分布

- **C**:MTEXT 高度 2.5、H 改高 **10**、SCALETEXT 选项默认值 `<2>` / `<1>`、`1 个对象已更改`
- **D**:字体下拉框「新宋体」、568.0s 特性面板 `旋转 0`、正文字符串
- **L**:两块 MTEXT 的插入点、框宽 60 / 80
- **M**:无

## 做不到的部分

- MTEXT 的**正文**与**框宽**永远不在命令行回显;框宽全课靠鼠标拖,无法升到 C 级。
- 399–456s 的夹点拖宽是纯交互演示,终态被后续 MTEXT 覆盖,不复现。
- 593–687s 的 SCALETEXT(含 `比例因子 <2>` / `参照 R` 分支)只有过程回显、
  最终作用对象与新长度均为屏幕拾取,无法确定被改对象与目标高度,**未纳入脚本**。
- `_Find`(775.9s)是对话框操作,无命令行数值,不纳入。
- `MTEXTED :lisped` 是无头环境规避就地编辑器的手段,不是课程内容。
