## 构造

`l38.scr` 把全课编成**九个演示分区**:

| # | 脚本 | 演示内容 | 数值出处 |
|---|---|---|---|
| 1 | `_.LINE 0,0 1000,0` + `_.BREAK 400,0 600,0` | **两点打断** | 61.0s BREAK;**长度 1000 / 打断点无出处** |
| 2 | `_.LINE 0,-300 1000,-300` + `_.BREAK 200,-300 **_F** 300,-300 700,-300` | **第一点(F)方式** | **86.9s `[第一点(F)]: F`** |
| 3 | `_.LINE 0,-600 1000,-600` + `_.BREAKATPOINT 300,-600 500,-600` | **定点打断** | **250.1s `_breakatpoint`** |
| 4 | 两条首尾相接的直线 + `_.JOIN 200,-900 700,-900` | **合并** | **319.2s `2 条直线已合并为 1 条直线`** |

| 6 | `_.LINE 0,-2600 **649.33**,-2600` + `_.DIMLINEAR …` | **线性标注** | **786.2s `标注文字 = 649.33`(D)** |

> 降级 `TEXT`(**保持同一字高**),写明实体类型变了」。
> 脚本保留了 688.3s 读到的 **字高 2.5**,只把实体类型从 MTEXT 换成 TEXT。

## 验证(verify.json)

```
l38.dxf  counts = { LINE: 9, CIRCLE: 3, DIMENSION: 1, WIPEOUT: 1,
                    LWPOLYLINE: 1, HATCH: 1, TEXT: 1 }
CIRCLE[0] = c(3000, -1800) r 500
CIRCLE[1] = c(5400, -100)  r 250
```

**四条自校验,全部通过:**

**1. `SCALE 10` 被半径证明**
脚本画的是 `_.CIRCLE 3000,-1800 **50**`,DXF 里却是 **r = 500** ——
**正好放大 10 倍**,与 697.0s 命令行的 `10` 逐位一致 ✓

**2. `LINE: 9` 把打断 / 合并 / 去重三种行为一次性算清**

| 分区 | 画了几条 | 操作后 |
|---|---|---|
| 1 两点打断 | 1 | **2** |
| 2 第一点(F)打断 | 1 | **2** |
| 3 定点打断 | 1 | **2** |
| 4 JOIN 合并 | **2** | **1** |
| 6 标注用的线 | 1 | 1 |
| 9 两条重合线 + OVERKILL | **2** | **1** |
| **合计** | **8** | **9** ✓ |

**打断使数量 +1、合并使数量 −1、去重使数量 −1** —— 三种相反的行为
在同一份 DXF 里同时被证明,这是本课最有力的一条 ✓
(其中 **OVERKILL 把 2 条完全重合的线删成 1 条**,正对应 882.2s 的
**`2 个重复项已删除`**。)

**3. `CIRCLE: 3`** = 缩放后的大圆 + `_.COPY` 出来的副本 + 区域覆盖上的小圆 ✓

**4. 标注回读值**
DXF 里有 `DIMENSION: 1`,标注的正是长度 **649.33** 的那条线 ——
与 786.2s 的 **`标注文字 = 649.33`** 一致 ✓
(该值是**由标注回读反推的线长**,再由回放后的标注复现同一个数,闭环成立。)

## ⚠ 数值出处核对 —— 关键发现

### 结论:**知识点数值(10 / 2.5 / OFF / B / F / 649.33)全部可追溯并被 DXF 复验**

尤其是 **`SCALE 10`** —— 脚本画 r=50、DXF 得 r=500,
**放大倍数被实体属性直接证明**;
以及 **`OVERKILL`** —— 画 2 条重合线、DXF 只剩 1 条,
**与 882.2s 的 `2 个重复项已删除` 一致**。

### 无出处的数值

```
圆半径 50(缩放前)、圆半径 250        直线长 1000 / 800 / 400
BREAK 的打断点 400,0 / 600,0 / 300,-300 / 700,-300 / 500,-600
区域覆盖 5000,-400 → 5800,200        矩形 7000,-400 → 7800,200
`_.COPY` 位移 (2000,-1800)→(2000,-1000);`_.MOVE` 位移 (0,0)→(0,-100)
九个分区的摆位
```

`out/replica/l38/` 下有 `build.py`(脚本生成器)但**没有测量产物**;
视频里 `CIRCLE` / `RECTANG` / `LINE` 全程鼠标拾取,**一次数值回显都没有**。

**影响评估:低,但有一处需要注意** ——
`SCALE 10` 的**验证**依赖"缩放前半径 50"这个无出处值:
DXF 的 `r = 500` 只有在已知源半径 50 的前提下才能证明倍数是 10。
好在 50 是脚本自己写的、且回放日志里可查,**内部自洽**;
但它**不能与视频比对**(视频里那个圆的真实半径不可知)。

### `-HATCH` 的三个参数无出处

`_.-HATCH _P **ANSI31** **1** **0** 7400,-100`:
`ANSI31` 是默认图案、角度 `0` 是默认值,**比例 `1` 完全无出处**。
视频里讲师是在**对话框**里挑的,命令行零回显,且 419.0s 那次最后 `*取消*` 了。

### 未采用的证据(1 条)

**760.3s `前置 [文字(T)/标注(D)/引线(L)/全部(A)] <全部>:` → `已前置 1 个对象。`**
—— `TEXTTOFRONT` 命令,脚本没有做。
它与 `DRAWORDER` 属同一知识点(叠放次序),脚本已用 `_.DRAWORDER _B` / `_F` 覆盖。

## 做不到的部分

1. **全部几何尺寸与位置无出处**(见上),本文档不为它们背书;
   其中**缩放前的圆半径 50** 影响 `SCALE 10` 的验证可比性。
2. **`-HATCH` 的图案 / 比例无出处**,填充在视频里也从未真正落地(419.0s 被 `*取消*`)。
3. **`MTEXT` 降级为 `TEXT`** —— SOP 坑表要求;**实体类型变了**(DXF 里是 `TEXT` 而非 `MTEXT`),
   但**字高 2.5 是 C 级、保持一致**。
4. **`WIPEOUT` 与 `DRAWORDER` 的视觉效果无法验证** —— 无头环境无显示,
   只能确认命令执行成功、实体仍在。
5. **`TEXTTOFRONT` 未复现**(见上)。
6. **讲师全程鼠标拾取打断点 / 基点** —— 脚本的点位是按靶子几何算出来、
   保证落在实体上的(SOP 坑表要求),**不是视频里的真实点击位置**。
7. **`OVERKILL` 的「15 个重叠对象或线段已删除」(845.3s)未复现** ——
   那需要一堆部分重叠的线段,视频里是讲师前面画乱的结果,不可知;
   脚本只复现了**「2 个重复项已删除」**(882.2s)这一条,即完全重合的两条线。
