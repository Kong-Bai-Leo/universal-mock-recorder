# 录屏视频 → Mock 操作程序:需求与验收规范

版本 v0.3 · 2026-08-28 · 状态:CV 层已收敛,agent 层待接管

---

## 0. 一句话目标

给定一段**真实软件操作录屏**,自动产出一份**可执行、可验证的 Mock 操作程序**;
它必须**按视频里的同样步骤、同样顺序**复现,而不是"看懂结果后另找一条路做出同样的东西"。

## 1. 铁律(此前踩过的坑,已固化为硬性要求)

| # | 要求 | 反例(曾经发生) |
|---|---|---|
| R1 | **必须由 CV 走完整段视频**产出步骤序列,不允许人/agent 跳看视频后凭结果重建 | 课时123 第一版:读了标题页尺寸就直接建模,步骤与视频无关 |
| R2 | 复现的是**过程**:命令、顺序、参数都要来自视频证据 | — |
| R3 | 视频里的**取消、撤销、重画**必须被识别并记录,但不进入最终执行序列 | — |
| R4 | 任何数值必须有**证据出处**(命令行回显 / 标注文字 / 像素测量),不得推测 | — |
| R5 | 完成后必须做**独立验证**(几何量 ≠ 生成脚本自身的输入) | — |
| R6 | 报告必须**如实标注置信度**:实测值 / 命令行确认值 / 推断值分开写 | 课时8 第一版把徒手画的演示图理想化成 3-4-5 三角形 |

## 2. 管线四层

```
录屏视频
   │
   ├─[1] CV 层     纯几何:光标/输入事件/变化片段/稳定帧/证据切片/命令行条带
   │                零 OCR、零 VLM、零语义判断
   ▼
证据包(见 §3 输出契约)
   │
   ├─[2] Agent 层  一切"看懂":读命令行文字、读按钮文字、判语义、剔无效操作
   │                产出 MockWorkflow(仓库既有 schema)
   ▼
semantic-trace.json / mock-script.ts / computer-use-task.md
   │
   ├─[3] 回放层    按同序执行到真实软件(AutoCAD accoreconsole / Mock Runtime)
   ▼
DWG / DXF / 截图
   │
   └─[4] 验证层    MASSPROP 体积、包围盒、标注文字回读、逐线像素比对
```

**分界线**:CV 管"哪里、什么时候、什么范围变了";agent 管所有"看懂"——**包括看懂字**。

## 3. CV 层输出契约(固定,下游只依赖这些)

工具:`prototype/cv/probe.py`(v3.0,已收敛,替代早期三个原型脚本)

```
py -3.11 cv/probe.py <video.mp4> <out_dir> [--layout auto|acad720|acad1080] [--start S] [--end S]
```

| 文件 | 内容 |
|---|---|
| `manifest.json` | 视频元数据 + 采用的布局 + 工具版本 + 统计 |
| `trajectory.json` | 逐帧光标 `{f,t,x,y,sx,sy,found,mode}`,mode ∈ cross/diff/none |
| `input_events.json` | 输入事件 `{id,t0,fCrop,cursorAt}`(按键可视化覆盖层) |
| `episodes.json` | UI 变化片段 `{id,t0,t1,bbox,peakPx,dominantRegion}` |
| `actions.json` | 候选动作 `{id,type,t0,t1,cursor,bbox,inputs,cursorPathPx}` |
| `cmdstrips/` | 命令行区域变化条带,原生分辨率,时间序 |
| `cmdmont/` | 条带蒙太奇(每张 16 条),供 agent 批量读取 |
| `slices/` | 每动作证据包 |
| `index.html` | 人工复核页 |

**CV 明确不做**:不判断哪些操作"没意义"(只打低置信度标记,删除权归 agent);
不猜快捷键(只报告"无点击的状态变化");不输出绝对坐标给最终脚本。

### 3.1 布局配置(换视频源只加一条,算法不动)

| 名称 | 分辨率 | 场景 | 命令行区 | 按键覆盖层区 |
|---|---|---|---|---|
| `acad720` | 1280×720 | 课时 4–15,单视口 | (0,598)-(1050,672) | (1060,585)-(1255,672) |
| `acad1080` | 1920×1080 | 课时 123–127,左2D/右3D 双视口 | (0,916)-(1500,1006) | (1600,938)-(1835,1008) |

`--layout auto` 按分辨率自动匹配。

### 3.2 素材前提(有则精度高,无则退化)

| 信号 | 有无 | 影响 |
|---|---|---|
| 全屏十字光标 | 本教程有 | 光标定位 73–89% 帧直接命中;否则退化到帧差分兜底 |
| 按键可视化覆盖层 | 本教程有(连"左键"都显示) | 输入时刻精确到帧;否则点击只能靠"停顿+突变"推断 |
| 命令行回显 | AutoCAD 天然有 | 命令与参数可 1:1 提取;否则只能靠视觉推断 |

## 4. 证据包规格(每个动作)

| 图 | 分辨率 | 用途 |
|---|---|---|
| before / after 全帧 | 降采样,叠加光标标记 | 全局上下文、验证条件 |
| **target 特写**(光标 ±90px) | **原生** | 让 agent 看清按的是哪个按钮/图标 |
| 变化区裁剪 before/after | 原生 | canvasChange 直接证据 |
| 轨迹叠加图(拖拽/绘制) | 降采样 | 起终点 + 完整路径,几何测量依据 |
| 输入覆盖层裁剪 | 原生 | 读出具体按键 |

**全帧上必须画出光标标记**——降采样后光标只剩几像素,标记把"点了哪里"从推理题变成看图题。

## 5. 回放层要求

1. 脚本必须**逐条对应**提取出的命令序列,顺序一致;
2. 无头 AutoCAD(accoreconsole)缺图形管线,以下替代**必须显式记录**在脚本注释与报告中:

| 视频命令 | 无头替代 | 原因 |
|---|---|---|
| 快速 TRIM 点选 | 标准模式 + 栏选 `_F` | 无显示,快速点选拾取失败 |
| JOIN | PEDIT `_M` + `_J` | JOIN 首问是单选源对象 |
| PRESSPULL | EXTRUDE | PRESSPULL 需面内点击 |
| LOFT 逐个点选 | 只存在两截面时 `_ALL` | 投影重叠导致点选有歧义 |
| 布尔运算点选 | 点在**实体边**上,不能点面内 | 无显示时面内点击被当成窗选起点 |
| FILLET `_R` 后接倒角 | 拆成两条 FILLET 命令 | 本版设完半径即退出命令 |
| PLINE 圆弧段首段给端点 | 用圆心 `_CE` 或第二点 `_S` 确定 | 无前段切向, 方向退化被拒(`*Invalid*`) |
| 渐变填充 GRADIENT | 退化为 SOLID 实色填充(色阶丢失) | `-GRADIENT` 命令不存在;`-HATCH _P _G <名> <角>` 之后仍有一步交互提示无法脚本化 |

3. 所有拾取点必须落在当前 ZOOM 窗口内,否则单点会被解释成窗选起点;
4. `.scr` 中空行 = 回车;多一个空行会重入上一条命令(高频事故源);
   行尾空格已是回车,后面再跟空行同样会重入;
5. **SAVEAS 覆盖确认会挂死** —— 目标文件已存在时弹确认框,无头下无人应答。
   回放前必须先删旧产物,并给进程加硬超时(见 `run_lesson.ps1`);
6. **填充边界检测依赖当前视图** —— 图形在视图外时报 "Valid hatch boundary not found",
   填充前必须 ZOOM 到覆盖全部边界(与 TTR 需要 ZOOM E 同源);
7. POLYGON 参数顺序是 边数 → 中心 → 内接/外切 → 半径,选项在中心之后。

## 6. 验证层要求(至少满足两项)

- **MASSPROP 体积**与解析计算值一致(小数点后 2 位);
- **包围盒**与标题页尺寸链一致;
- **标注文字回读**:回放后由 AutoCAD 自己量出的 `标注文字 = N` 与视频标注一致(这是独立旁证,不是脚本输入);
- **逐线像素比对**:复刻渲染图与视频原帧的线段/圆逐条对上。

## 6.5 CV 工具集(已收敛)

| 工具 | 职责 |
|---|---|
| `cv/probe.py` | 全片探测:光标/输入事件/变化片段/稳定帧/证据切片/命令行条带+蒙太奇 |

| `run_lesson.ps1` | 清旧产物 → 回放(硬超时)→ 校验 |
