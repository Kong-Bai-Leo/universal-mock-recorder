# 录制器回放验证

验证对象是“录制证据到目标状态”的链路，不是文件是否生成。先选定用户指定的录制、代码版本、后端、起始场景以及期望的操作/形状/尺寸精度。

## 分层验证，分别报告

| 层级 | 能证明 | 不能证明 |
|---|---|---|
| Schema 与本地语义校验 | 字段、引用、受支持参数及算术符合规则 | VLM 看到了正确对象/数字 |
| 合成/模拟 VLM 测试 | 预期输入到选择、IR、编译器的契约 | 真实模型识别准确率 |
| 本地录制证据回归 | 指定事件/截图完整关联并进入输入 | 真实 API 已收到或模型已正确理解 |
| 隔离应用执行 | 该结构化脚本在该场景的实际行为 | 源录制已被正确识别 |
| 真实录制端到端对照 | 此样本的操作覆盖与几何/视觉误差 | 任意软件/视角/流程的普遍准确性 |

选择与改动风险相称的层级；没有执行的层级明确写“未测”。以前通过的结果标注版本，不冒充本次执行。不要将模拟返回用于报告真实模型命中率。

## 必查不变量

- 每个有持久贡献的操作都已表达，或有明确遗漏及依赖。后续多个错误应能追溯到最早缺失，而不是用假 ID 补齐。
- 每个选择引用在该时刻存在，且对象类型、坐标系、拓扑版本、数量及几何保护吻合。AutoCAD 阵列成员/替换实体，Max copy/instance/面版本都需覆盖。
- 正确识别按钮并不证明选中了正确线段或面。已上传数值图不证明数字可读；数字精确也不证明其语义正确。
- 参数的来源与置信度不可为通过校验而修改。近似值有独立标记，未知项不静默填默认值。
- `complete` 应描述覆盖状态，不自动代表尺寸精确。近似参数全部执行仍是 approximate；缺少前置操作仍是 partial。
- 对称/重叠对象或遮挡导致歧义时测试拒绝路径。未观察到的面不自动删除，新出现的面不自动视为新创建。

## 实机运行与对照

优先使用合成空白场景、单独文件或独立批处理进程。检查是否会重置场景、覆盖文件、保存到用户目录、或执行任意脚本；未经相应授权不操作用户当前工作场景。保留现场，不杀无关进程。

先检查脚本依赖及选择保护，再执行。只对本次启动的进程做超时处理。几何断言、应用日志、最终标记和进程退出状态分别记录；断言通过但退出超时应报告两者，而非笼统称全部通过。

对照时分开评价：对象数量/选择身份、命令与操作覆盖、拓扑连接/删除区段、长度/角度/位置、视口呈现。固定或记录视角/缩放/投影；配准后的图像相似度不能替代尺度、深度或拓扑检查。

近似三维参数评估要有独立真值、预先定义的容差和未参与调参的样本。记录绝对/相对误差、方向正确性、覆盖率及拒绝率。模型自报的范围不是经过校准的误差界限。

## 本项目可复用入口

从用户指定项目根目录运行/检查，避免把技能安装目录当项目：

- 离线测试：`node --test tests/*.test.mjs`；先检查测试是否调用外部服务或目标应用，必要时选单个相关文件。
- CAD 重点：`tests/analysis-harness.test.mjs`、`tests/cad-context.test.mjs`、`tests/cad-derived-geometry.test.mjs`、`tests/cad-program-normalizer.test.mjs`。
- Max 重点：`tests/threedsmax-evidence-policy.test.mjs`、`tests/threedsmax-bevel.test.mjs`、`tests/threedsmax-approximation.test.mjs`、`tests/threedsmax-visual-faces.test.mjs`。
- 可选实机入口：`scripts/test-3dsmax-bevel.mjs`。先读取当前实现并确认安装路径、输入场景和许可范围；该入口不是普通离线测试。

## 交付与回归资产

交付简短结论、样本/代码版本、已测层级、通过/失败项、剩余风险与下一步。修复请求另改生成链路，不能手改输出文件之后声称回归通过。

可提交合成最小 fixtures 和必要断言；真实录制、原图、请求体、场景和密钥默认留本地。只有明确授权才调用付费模型或上传样本；预先说明范围与请求上限，失败保留已有结果，停止在预算或修复上限内。提交/push 也是独立动作，不因测试通过自动执行。
