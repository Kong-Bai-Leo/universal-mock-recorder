# 新软件 Recorder 从零适配与复刻任务书

> 可直接交给另一位 AI 执行的任务说明，2026-09-16。目标是交付**可复用的软件适配系统**，不是人工写出某一次录制的回放脚本。以下阶段按证据逐关推进；未获授权的实机操作、上传、付费请求和提交均停在相应关口。

## 0. 接手时填写的最少信息

| 项 | 待填写 | 不明确时的默认处理 |
| --- | --- | --- |
| 目标软件 | 名称、版本/构建号、界面语言、工作区/插件、许可证状态 | 先只读核实；版本未知不把其他版本的手册或 UI Map 当已验证 |
| 环境 | 仓库根目录、采集机/分析机/执行机、操作系统、显示分辨率 | 记录实际主机和构建版本；无法操作的机器只做离线设计 |
| 首轮范围 | 3–8 个可闭环操作、一个安全合成样本、一个变体和至少一个拒绝样本 | 先拟最小范围请用户确认；不承诺全软件、全按钮或任意工程 |
| 交付/精度 | 预期原生文件、运行方式、结果对象与容差；视频-only、UIA-off 或事件+截图 | 未指定时按事件+截图基线设计；其他模式分别标“未测”，不自行推定绝对尺寸 |
| 授权/预算 | GUI 扫描、录制、隔离执行、外部手册、付费 API、上传素材、请求/费用/修复上限、commit/push 各自权限 | 默认不上传、不调用付费 API、不碰用户当前场景、不提交或 push；需要哪项就说明范围再请求 |

开始前检查 `git status`，保留所有其他任务的未提交改动。完整阅读仓库的 [AGENTS.md](../AGENTS.md)、[recorder-adapter](../skills/recorder-adapter/SKILL.md)、[recorder-diagnose](../skills/recorder-diagnose/SKILL.md)、[recorder-verify](../skills/recorder-verify/SKILL.md)，以[经验与 Agenda](recorder-skills-and-agenda.md)作方法和验收参考。仓库技能是维护源；个人安装副本若不同，核实差异，不静默覆盖。用户新要求优先于旧 Agenda。

已有明确授权在其范围内继续有效，不逐次重复询问；仅在目标、上传内容、付费预算、覆盖风险或其他权限范围扩大时补充确认。本文本身不授予任何权限。本任务书可脱离原聊天阅读；若迁移到另一个仓库，先把下列模块路径映射到新仓库，缺少的模块按契约实现，不假定本项目文件已随文档交付。

## 1. 一页总流程与停靠点

```text
环境/许可/授权核实
  → 同版本官方手册与合法接口研究
  → 安全空白场景实际 GUI scan
  → 静态 UI Map + 独立 live observation + 命令/接口目录
  → 复用通用采集器，建立新软件独立入口
  → 真实事务录制，按前/中/后状态组织可追溯证据
  → 有界模型输入，输出操作 + 模型选择的合法 apiCall
  → 本地语义校验、对象状态与受控原生单文件编译
  → 合成离线/隔离原生执行/真实录制端到端分别验证
  → 最早错误层修复、回归、支持矩阵、授权后提交
```

每一箭头都要留下输入版本、证据与产出。可在未授权关口完成安全的只读/合成工作，但不得将后续关口写成“通过”。四层分开：系统输入与截图采集 → 应用 UI/命令知识及状态推断 → 结构化操作与本地校验 → 原生脚本或其他回放后端。**基础采集不得依赖目标软件内部数据接口**；可选内部接口采集要单列能力和前提。执行与独立验收可以合法使用目标软件提供的原生接口。

## 2. 分阶段执行

### A. 环境、边界和授权

- **输入：** 上表、当前仓库、目标软件安装与许可证信息。
- **操作：** 核对精确版本/语言/工作区、安装组件、许可证能力、采集与分析执行所在机器；记录仓库提交或工作树状态、二进制/配置版本。列出首轮支持的操作、输出形式、误差和不可见依赖。确认是否准许使用 GUI、网络、付费 API、用户文件、保存路径、提交及 push。识别用户当前场景和敏感窗口，规划新的空白/合成文件与独立输出目录。
- **产出：** 范围与授权表、版本/主机清单、首轮样本与独立真值计划。
- **通过门槛/失败处理：** 版本、许可和权限足以推进下一阶段；缺许可/组件时明确阻塞及替代离线范围，不改系统许可、不借其他软件的验证冒充目标软件。

### B. 官方手册与接口研究

- **输入：** 已核实的软件版本和首轮操作。
- **操作：** 查目标版本官方 UI/脚本/API 文档，登记命令名、参数、对象类型、默认行为、异步状态、保存/重开能力和来源 URL/章节；识别哪些是 GUI 操作、哪些可由原生接口重建。按操作建立允许列表：接口/调用类型、接收对象、参数类型、结果绑定、先决条件、危险副作用。研究是否允许单文件携带文本源、资源或配置；无法内嵌的依赖必须有显式边界。
- **产出：** 带来源、适用版本和核实状态的命令/接口目录；最小端到端语义契约。
- **通过门槛/失败处理：** 首轮每项操作都有可验证的回放路径或明确“不支持”。手册存在不等于安装环境已观察；找不到合法接口时停在研究/候选，不让模型自由拼接任意脚本。

### C. 实际 GUI scan：先层级，后布局

- **输入：** 可操作的目标软件、许可范围、安全空白场景、待扫描功能表。
- **操作：** 在实际版本里按 tab/section → panel → control → split button 的主按钮/箭头 → menu item/对话框逐层扫描。为纯图标按钮记身份、功能、上下文和可见状态；区分主按钮直接动作与箭头展开项。只读或可撤销地试探安全功能；删除、覆盖、提交任务、连接硬件、云同步等危险按钮不盲点。记录窗口/工作区、缩放、时间、可见文本、截图原图及控件边界，必要时观察启用/禁用状态及阶段变化。
- **产出：** 分页面/面板的静态 `ui-map.json` 与单次布局的 `live-observation.json`；未扫描清单。静态条目存层级、canonical 名称、别名、功能、版本、来源、核实状态；具体 `bounds` 只在 observation 中，不作为跨分辨率固定坐标。
- **通过门槛/失败处理：** 首轮要用的控件能从实际画面定位到父级、功能及状态；不能扫描的项标“文档候选/未观察”。没有 GUI 权限只可做文档目录，不能称“实机扫描”。进程过滤只能减少误收集，**不能代替截图隐私隔离**；扫描前需核对画面上是否有敏感内容。

### D. 独立 recorder 入口与基础采集

- **输入：** 现有共享采集器、目标进程/窗口判定规则、UI Map。
- **操作：** 先检查当前代码结构；在 Windows 上优先复用现有 C#/WinForms [共享原生采集器](../src/Recorder.Native/Recorder.cs)，给新软件独立 profile、入口和构建脚本；其他操作系统须另实现采集后端，只复用证据/IR/分析和编译契约。分析侧设置独立 `src/analyzer/<app>-cli.mjs`，在 `lib` 中区分 evidence、knowledge、program、renderer。路径是导航示例，以当前代码为准。采集标准输入事件、时间戳、目标窗口、操作前/后及必要中间截图、焦点/几何信息；尽量保留原图及裁剪映射。UIA 可关闭，作为辅助元数据而非唯一依据；目标软件内部接口采集只能是单列的可选增强。包/进程匹配不自动保证只截到非敏感内容。
- **产出：** 可启动/停止的新入口、录制 manifest、事件与图像索引、版本/主机追踪、合成空白场景采集样本。
- **通过门槛/失败处理：** 输入/截图时间与窗口对应，暂停/切窗不会误归因，停止后文件完整；打包清单不含 `.env`、密钥、旧录制和请求体。若视频-only，不能假设存在按键、Automation ID 或专有事件；`UIA-off` 仍有鼠标键盘日志，**不等于**视频-only，必须分别测试。

### E. 真实事务录制与证据策略

- **输入：** 用户许可的安全样本、首轮操作、采集入口。
- **操作：** 把有持久贡献的动作当完整事务，而不是平均采样帧：留前态、选择/预览、带标签参数、确认/计算中的状态、持久后态及全局定位图。对异步报告、工程运行、重绘和多阶段工具，补取有真实时间戳的 settled/terminal 状态；名称为 `after` 不保证晚于完成。局部裁剪保留原图坐标/缩放映射。记录被排除的证据及原因，预算不够时暂停或降范围，不静默丢关键前后图。另存独立原始真值，**不送给模型补答案**。
- **产出：** 首轮真实录制、证据清单、事务边界、独立真值与容差（留本地）。
- **通过门槛/失败处理：** 每项操作可追到来源事件、时间区间、目标窗口、阶段、选择对象、参数证据及最终状态。粘贴内容/外部源文件未被录下时标未知依赖，不从 Ctrl+V 或文件名编造内容；未观察到最终状态标 pending/unknown。录制、原截图、请求体和用户场景默认不入 Git。

### F. 有界模型输入、知识检索和跨段状态

- **输入：** 证据包、UI Map/命令知识、合法接口目录、前段状态。
- **操作：** 按事务分段、只检索相关 UI/接口条目，送有预算的前中后证据及全图/裁剪映射；保留原始图片与实际成功上传图片的对应清单。提示模型先定 active command、stage、选择层级与参数角色，再解释文字/数字，遇冲突比较同一时刻画面、输入与命令状态。模型输出语义操作、证据引用、精度标签，并在该软件契约需要原生接口时**自己选择合法 `apiCall`、接收对象、参数及结果绑定**；本地只验证，不暗中补命令冒充模型选择。跨段传稳定对象目录、拓扑版本、pending/deferred 事务、遗漏依赖和有界摘要，不重复发送整段历史。把 UI Map、接口目录、schema、提示与输入摘要纳入版本/检查点身份；变化后按规则失效，不混用旧响应。
- **产出：** 逐段原始响应、解析后的操作/接口计划、实际输入与 usage/尝试记录、可续接状态。
- **请求组织：** 一次请求包含任务与输出约束、当前段事件/事务、相关知识与接口条目、前段必要状态，以及有标签的真实图像输入；只写图片路径不会使模型看到图片。上传前核对实际载荷中的图片字节、时序和原图映射。遇到状态栏坐标、单位或参数标签的小字号，先检查实际请求分辨率与可读性，再选择高清原图或带定位全图的局部裁剪，不能统一缩成低清后要求模型猜数值。使用当前 provider 支持的图像参数，并把新增图片/token 成本计入预算；配置了什么模式不等于模型确已读对。
- **通过门槛/失败处理：** 结构、来源 ID、参数角色、对象绑定、complete/pending/unresolved 自洽；未命中知识时列有限候选和不确定性，不把最相近候选自动升级为确定。传输失败、无响应、结构失败和语义失败分开计数；设请求数、图片/token、费用估算与修复次数上限，默认无无限自动重试。扩大预算必须得到用户明确授权；成功 usage 与无 usage 失败分别报告。

### G. 结构化 IR、状态生命周期与受控编译

- **输入：** 模型计划、接口允许列表、当前对象/拓扑目录、交付契约。
- **操作：** 用确定性本地代码做 schema 与语义校验：对象在引用时必须存在、类型/数量/坐标系/拓扑版本相符；复制/实例、替换、删除、阵列/派生成员有合法前后继；视觉面 ID 与运行时面编号分开。数值记录角色、单位、绝对/相对模式、来源及 exact/approximate/unknown，缺参照不补绝对尺度。受控编译器仅能调用允许接口、生成隔离路径并防覆盖；模型不得自由拼接可执行代码。最终主交付是可直接在目标软件运行的**一个原生文件**（后缀依软件而定），内部 JSON、日志和调试结果另存；受支持且已知的依赖可安全嵌入，未知或不可携带的外部依赖要拒绝或明示，不能虚构。
- **产出：** 版本化 IR/接口计划、验证结果、受控编译器、单文件主交付及依赖边界。
- **通过门槛/失败处理：** 非法引用、过期身份、歧义选择、数量不符、无来源估值、任意脚本或覆盖路径被拒绝；`complete` 仅表示持久操作覆盖，不自动代表尺寸精确。已完成但不能表达的修改列为 unresolved/omitted 并保留依赖，不抹成无意义输入。不手改某次生成文件或硬编码该作品来让验收过关。

### H. 分层验证：离线、原生、真实 E2E

- **输入：** 合成 fixtures、原始录制、受控脚本、独立真值、授权的目标软件。
- **操作：** 先核对测试副作用，再显式运行相关离线文件（例如 `node --test tests/<app>*.test.mjs`；勿用无边界自动发现误触原生测试）。至少测合法、变体、缺参、歧义、过期 ID、预算暂停和拒绝路径，并回归共享逻辑。实机只在新空白场景/新目录或本次启动的隔离进程执行；先检查脚本依赖、可能的场景重置/外部动作与覆盖风险。记录脚本哈希、实际粘贴/执行内容、日志、最终标记、退出状态；保存、关闭、重开，独立读回对象、属性、连接、尺寸/统计/运行结果，并与**分析前保存、未送模型的原录制真值**对照。视图比较要固定/记录视角、缩放和投影，不能代替拓扑或数值断言。
- **产出：** 分层测试记录、原生执行证据、保存重开结果、真实样本误差/遗漏表。
- **通过门槛/失败处理：** 严格分开“已实现、离线通过、合成原生通过、真实录制 E2E 通过”；模拟模型返回不算真实识别率，脚本生成/运行不等于结果一致。脚本若只完成一部分、原生任务有警告/资源失败、保存重开未测，都分别报告；后端暂不支持保存重开时列未通过/未支持，不能跳过后称通过。断言通过但进程退出超时也分别记录。没有授权时实机/付费层级写“未测”。

### I. 失败诊断、修复闭环与交付

- **输入：** 失败样本与完整证据链。
- **操作：** 沿原始事件 → 选入且实际上传的图 → 模型响应 → 语义/身份校验 → 编译脚本 → 原生行为 → 独立真值，停在**最早有证据的偏差**。判断是采集缺口、知识/阶段误判、模型输入/输出、IR 无法表达、编译错误、原生环境/许可，还是对照方法问题。只在最早层做通用修复，补合成正反例和受影响适配器回归；改输入/schema/知识后检查 checkpoint 是否应失效。保留旧失败和原响应，允许有条件零 API 离线重编译，但不改写历史为成功。
- **产出：** 失败根因、代码/测试、复验报告、逐操作支持矩阵、运行说明与单文件主交付。
- **通过门槛/失败处理：** 每个宣称支持的操作列证据模式、接口、精度、已编码/离线/原生/真实 E2E 层级和未覆盖边界；修复上限触发则暂停并说明剩余不确定性。交付前逐文件审查改动与必要依赖，保留其他任务的工作，不直接暂存整个工作树。只有用户授权包含 commit/push 且发布内容不含原录制、密钥或请求体时，才执行相应动作；既有授权足够时无需重复确认。技能或测试通过本身不授权提交。

## 3. 建议目录与最小契约示意

下列结构和字段是**新适配器待实现的示意契约，不是仓库已有的统一 schema**。可按当前代码调整命名，但保留层次、来源和版本；已有接口需写兼容/迁移规则，不静默覆盖旧录制。

```text
src/Recorder.Native/Recorder.cs            # Windows C#/WinForms 共享输入/截图采集
src/Recorder.<App>/                       # 独立 profile/入口（或当前仓库等价结构）
src/analyzer/<app>-cli.mjs                 # 分析入口
src/analyzer/lib/<app>-evidence.mjs        # 事务/证据选取
src/analyzer/lib/<app>-knowledge.mjs       # UI、命令、接口检索
src/analyzer/lib/<app>-program.mjs         # IR、状态与校验
src/analyzer/lib/<app>-renderer.mjs        # 受控原生文件编译
ui-maps/<app>/                             # 分 panel 的静态 map 与扫描说明
tests/<app>*.test.mjs                      # 合成/拒绝/回归
scripts/build-<app>-recorder.*             # 构建与无密钥打包
```

下面为便于阅读将静态控件与布局观察并列展示；实际分别存入 `ui-map.json` 与 `live-observation.json`，以 ID 关联。大 UI Map 的各页面/面板另存文件，由根索引引用。

```json
{
  "schemaVersion": "example-1",
  "application": {"name": "ExampleApp", "version": "x.y", "language": "en"},
  "control": {
    "id": "project.file.new.arrow", "parent": "project.file.new",
    "kind": "splitButtonArrow", "canonicalName": "New menu",
    "aliases": ["New ▼"], "function": "open new-item menu",
    "availableWhen": ["home"],
    "source": {"type": "observed", "observationId": "scan-001"},
    "verification": "observed-not-activated"
  },
  "liveObservation": {
    "id": "scan-001", "capturedAt": "ISO-8601", "window": "ExampleApp",
    "viewport": {"width": 1920, "height": 1080},
    "bounds": [20, 40, 60, 28], "originalImageRef": "local-only-image-id"
  }
```

## 6. 易误判处与判定原则

| 现象 | 正确处理 |
| --- | --- |
| 输入了数字/单字母选项 | 先看当前命令与阶段，再判是距离、角度、坐标、计数、选项还是侧点；数值要有角色、单位、模式和来源。 |
| 拖拽松开/点击确认、`after` 截图 | 可能只是预览、第一阶段或异步处理中；查持久后态、提示/任务状态，不以固定延时宣称完成。 |
| UIA 标签、文档名称或最近按钮很像 | 都是有来源的候选；同刻画面/提交状态不符时不得强行确定。纯图标和 split-button 箭头需分别识别。 |
| 屏幕上出现新线/新面/新对象 | 可能只是遮挡、视角或高亮变化；实体 ID 必须由合法创建/替换链产生，视觉面编号不能直接作为运行时编号。 |
| 一个早期操作漏掉、后续多项引用失败 | 追最早断裂的对象与跨段状态；不可为消除报错补“幽灵 ID”或默认选第一个。 |
| 像素移动、屏幕比例或 2D 上下方向 | 不等于 CAD 单位、3D 深度或局部坐标；仅有独立参照与视图条件才可标记近似值。 |
| 生成文件无错且能运行 | 只证明相应编译/执行层；还需保存重开、对象/连接/拓扑/参数及独立原录制真值对照。 |
