# AutoCAD / 3ds Max Recorder：经验与 Agenda

整理日期：2026-09-03。代码基线：`8d556ac`。本文总结两条录制器开发线，不把未提交的 KiCad 工作计入完成情况。Agenda 是后续工作清单，不是自动执行计划或日程提醒；本次不修改录制器功能。

## 最重要的结论

我们做的不是“让 AI 看图后写脚本”，而是维护一条可追溯链路：

```text
输入事件/截图 → 操作阶段与证据 → VLM 语义识别
             → 结构化操作 + 对象身份 → 本地校验/编译 → 回放对照
```

任何一层丢掉信息，后面增加推理强度都未必能补回来。SCR/MS 是验证和执行后端，修复目标始终是采集、分析与生成逻辑；不把某次画齿轮或建 Cylinder 的流程硬编码进去。

## 从两次开发提炼的经验

| 反复遇到的问题 | 应保留的方法 |
|---|---|
| UIA 标签和当前命令不一致 | ID、知识库、harness 都作为有来源的候选；用同时刻界面与实际提交核实 |
| ARRAY 的 I、ROTATE 的 C 被当新命令 | 在 active command + stage 下解析命令/选项，不按字母孤立匹配 |
| OFFSET 距离、侧点；Max 位置、旋转、缩放 XYZ 混淆 | 参数必须携带角色、单位、模式、选择层级和证据 |
| TRIM 小区段漏掉；Bevel 第二阶段缺图 | 以完整操作事务选前/中/后图，保留最终全图和局部原图映射 |
| 跨段漏一条线，后续操作连续失败 | 检查最早断裂的实体生命周期，续接状态与拓扑，不创建幽灵 ID |
| 把拖拽像素直接当尺寸 | 分开方向、屏幕比例和世界单位；有参照才采用明确标记的估算 |
| 截图识别 Polygon 与运行时选面混为一谈 | 视觉 ID、对象 ID、拓扑版本面 ID 分层，执行前检查数量/几何 |
| 上传所有图片后费用上升但仍不准 | 先保证证据完整，再做有预算的选图、分段续接与局部修复 |
| 能生成、测试通过被理解为完全还原 | 分开格式校验、模拟模型、实机脚本、真实端到端验证 |

三个概念也要分清：UI Map 是界面/命令知识；harness 是状态、证据和校验机制；skills 是开发助手处理任务的工作方法。这些技能不会自动进入 recorder 发给 VLM 的提示词，后者仍由分析器代码控制。

## 可复用 Skills

每个技能只处理一类任务，按需读取，而不是把全部历史塞进每次上下文。技能结构遵循 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。仓库内保存可维护源文件：

| 技能 | 何时使用 | 预期交付 |
|---|---|---|
| [recorder-diagnose](../skills/recorder-diagnose/SKILL.md) | 漏操作、尺寸错、生成失败、太慢/太贵 | 第一个出错层、证据、连锁影响与修复方向 |
| [recorder-adapter](../skills/recorder-adapter/SKILL.md) | 新软件/UI Map/新操作支持、证据链开发 | 清晰适配边界、结构化契约、支持矩阵与回归 |
| [recorder-verify](../skills/recorder-verify/SKILL.md) | 检查生成回放和录制是否一致 | 分层验证结果、覆盖/精度/拓扑误差、未验证项 |

示例请求：

- “用 `$recorder-diagnose` 检查最新 3ds Max 录制为什么漏了 Bevel，先不要调用 API。”
- “用 `$recorder-adapter` 设计下一个软件的 UI Map 与 recorder 适配，不依赖软件内部数据接口。”
- “用 `$recorder-verify` 检查这次修改，先跑本地测试；需要实机或付费分析时说明范围。”

这三个技能不规定固定模型、不内置个人路径/密钥、不自动上传录制，也不会默认 push。

本机已将三份技能安装到当前配置的个人技能目录，并与仓库源文件核对一致；以后修改源文件时需同步安装副本。上述链接始终指向仓库中的可维护版本。本次三份技能均通过 skill-creator 的格式校验；尚未进行独立任务中的行为评估。

## 当前状态：实现不等于已经验证完

- AutoCAD 已有 UI/命令知识检索、命令阶段 harness、结构化 CAD 操作、实体链、派生几何与 SCR 编译。历史上的 OFFSET/TRIM/ARRAY 等错误说明仍需要固定回归集，不能据此声称任意复杂 CAD 图形都能准确还原。
- 3ds Max 已有独立入口和 UI Map，支持基础对象操作；Editable Poly Bevel 有受保护的后端、视觉面目录以及有尺寸参照的近似参数路径。
- Max 的视觉面目录不是实际 mesh 拓扑；近似 Bevel 不是通用三维测量。Polygon Move/Rotate/Scale、通用 Extrude/Inset 回放尚未完整支持。详见 [证据策略](3dsmax-evidence-policy.md)、[视觉面追踪](3dsmax-visual-face-tracking.md)、[近似 Bevel](3dsmax-bevel-approximation.md)。
- 最近一次 Bevel 选图调整已做本地证据回归，不能替代付费 VLM 重新识别。合成场景的实机几何断言通过，但测试进程曾在退出阶段超时；延长超时后的干净退出仍需另测。

## Agenda：按依赖排序，而不是先把所有按钮全补齐

### P0-1：建立可复现的两应用验收集

每个样本记录操作意图、真值、输入模式、应选对象、关键参数、最终拓扑与允许误差。先覆盖已反复出现的 CAD 选项/吸附/修剪，以及 Max 创建/变换/复制/多阶段 Bevel。

验收：可以从同一输入比较两个代码版本的操作覆盖、参数误差、选择错误、耗时和实际 usage；区分本地、模拟模型和真实端到端结果。真实素材留本地，仓库只放合成或经允许脱敏的夹具。

### P0-2：先补三维选择与子对象编辑链

优先处理 Bevel 之前漏掉的 Polygon Move，再逐项扩展其他子对象操作。先定义局部/世界坐标、选面契约、拓扑修订及运行时保护，不能用移动整个 Cylinder 替代移动面。视频侧视觉面与运行时面关联单独验收。

验收：受支持简单样本中，只有选中面发生预期变动；错误对象、旧面编号、对称歧义与数量不符会被阻止；后续 Bevel 仍能合法引用新状态。尚不支持的情况清楚标注，不承诺任意网格。

### P0-3：真实验证近似 Bevel，而不只验证算术

使用有独立真值的短录制，覆盖正交/透视、不同缩放、正负 Height/Outline、松开后移动与最终确认；保留未参与调参的测试样本。

验收：分别报告方向、数值误差、接受率/拒绝率和选面正确率；不能用自报 confidence 或误差范围代替测量。没有有效参照、发生导航或选择歧义时按约定拒绝。付费分析另经授权，先约定请求上限与可接受误差。

### P1-1：证据按事务打包与跨段续接

整合命令阶段、参数角色、选择和完成状态。全图与局部图有统一时间/窗口/裁剪映射；小改动保留、预览不算完成、异步后图不串到下一操作。已完成但无法表达的修改进入待解决项及依赖列表。

验收：把分段边界移动到同一操作的不同阶段，最后得到一致的有效操作与实体链；预算不足有明确报告，不静默漏关键图或抹掉持久操作。

### P1-2：按阶段降本与降延迟

已有选图预算、检查点和有限修复继续沿用。重点检查 `3dsmax-cli.mjs` 的 `buildRepairFocus`：当前视觉面追踪开启时，语义修复会保留整段动作和图片；研究如何安全拆出局部修复与追踪依赖。先用真实 usage 找成本大头，不先换模型或盲目缩小图片。

验收：同一验收集、同一模型配置下，对比请求数、图片/token、实际费用、总耗时及失败率；只在不破坏关键证据和依赖的前提下接受优化。重试/修复有上限，可说明当前阶段，成功分段不因无关变化重跑。暂不承诺固定节省比例。

### P1-3：把回放验收做成独立、可重复的工具

与采集器分离，接收结构化计划/脚本和预期状态。使用独立场景，记录中间与最终对象、几何/拓扑断言及视图对照；为本地脚本后端和未来 Mock 留相同验收接口。

验收：生成成功、应用执行成功、结果符合期望是三个独立状态；歧义和错误选择不能静默通过，断言通过但进程超时要分别报告；不影响用户正在编辑的文件。

### P2：为视频输入及后续模型训练准备数据

先对相同任务做 UIA 开/关对照，再加入真正视频-only 测试。UIA 关闭仍有鼠标/键盘日志，不等于视频-only；视频需要额外估计事件边界和不可见输入。CV 可辅助配准、变化检测与候选定位，但不承诺从单视角恢复遮挡和绝对尺度。

训练前先定义“选起点/终点”的标签：原始帧及归一化位置、目标对象/面、命令阶段、视口状态、预期操作、可见性、精度来源与无解样本。按独立 session/场景拆训练和测试，不能把同一录制邻近帧随机分到两边。

验收：有不依赖 Automation ID 的基线、明确的无解/歧义指标和合法来源的数据集，再判断微调是否优于改采集、状态机和规则。此项不代表现在就开始训练。

## 执行顺序与完成口径

2026-09-12 用户补充交付要求：最终给用户一个能在目标软件内直接运行的文件，不要求用户另交 JSON 给执行 AI。内部仍按“AI 接口/参数 JSON → 校验 → 受控原生脚本”工作；将受支持且已知的资源嵌入脚本，未知外部依赖必须明确拒绝或报告，不能为单文件填造内容。已调整 Vivado 为 `vivado-replay.tcl`、JMP 为 `jmp-replay.jsl`；不代表其他旧适配器已全部迁移。JMP 当前重建最终数据与受支持分析，不宣称逐项复刻历史调用。运行文件和调试/证据产物分开，生成、执行和还原相同分别验收。

后续应用补充复盘：[JMP 复盘与 Vivado 迁移检查项（2026-09-12）](jmp-lessons-and-vivado-agenda.md)。涵盖模型返回接口的交付契约、异步后图、粘贴输入缺口、跨段完整性、默认对象、网络/预算和独立原生验收；新应用按实际语义迁移，不照搬JMP的固定等待时长或表格对象。

先做验收集和选择契约，再补 Polygon Move、验证 Bevel；随后完善事务与局部修复，最后扩大视频/其他应用覆盖。每项任务都记录“已实现什么、实际测过什么、未支持什么”。

技能负责复用做事方法；Agenda 负责决定下一步做什么。以后更新时只加入已证明会改变决策的经验，避免把每次错误都累积成一条全局禁令。
