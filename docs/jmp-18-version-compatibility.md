# JMP Pro 18 version routing and verification boundary

The earlier JMP adapter and its real-recording verification targeted **JMP Trial 19.1.5**, not JMP Pro 18. The Pro 18 VM was observed as **JMP Pro 18.0.0 (746439), English UI** on 2026-09-17. A subsequent [one-sample real-recording verification](jmp-pro18-real-recording-verification-2026-09-17.md) passed for Numeric/Continuous data and Distribution, including unchanged native JSL execution, save/reopen and independent GUI comparison. This does not certify all Pro 18 operations or builds.

## Analysis identity

The analyzer now requires an explicit `applicationVersion`, `applicationEdition`, and `language` from the recording manifest. A missing or `unknown` value may be supplied by `config.jmp.{version,edition,language}` or `--jmp-version`, `--jmp-edition`, `--jmp-language` after checking the actual installed application. If two sources conflict, analysis stops. Supported routes are `18.0[.x]` → `ui-maps/jmp/18/en-US` and `jmp-jsl-18-v1`, or `19.1[.x]` → `ui-maps/jmp/19.1/en-US` and `jmp-jsl-19.1-v1`. Versions 18.1/18.2 require their own UI verification and are currently rejected. An absent 18 map is an error, never a fallback to 19.1. The exact version and edition are retained in the preparation report, request, replay plan, and JSL comment. Changing these inputs invalidates a prior preparation/checkpoint. Old versionless manifests and saved runs are not silently upgraded.

The map is evidence of the particular UI scan stated in its index, not proof that every 18.x layout is identical. Routing currently requires the observed edition too: Pro for 18.0, Trial for 19.1. The VM's exact About/build value, license behavior, workspace and language must be checked before live analysis. The analyzer's explicit `apiCall` allowlist remains limited to table creation/rows/columns, renames, cell assignment, Distribution, Bivariate and Fit Line; Pro-only analyses are still unsupported.

## Official JMP 18 documentation check

The [JMP 18 Scripting Guide](https://www.jmp.com/content/dam/jmp/documents/en/support/jmp18/scripting-guide.pdf) documents `New Table` with `Add Rows`, `New Column` and `Set Values` initializers (Data Tables, around PDF p. 334), column creation and values (around PDF p. 400–401), and `Distribution`/`Bivariate` with `Fit Line` (Scripting Platforms, around PDF p. 491–498). The [JMP 18 JSL Syntax Reference](https://www.jmp.com/content/dam/jmp/documents/en/support/jmp18/jsl-syntax-reference.pdf) documents the table `Add Rows`, `Set Name`, `Save`, and `Run Script` messages (around PDF p. 375–400), column `Set Name` and `Set Values([matrix] or {list})` (around PDF p. 409–410), and `Open(path, ...)` (around PDF p. 139). These support the bounded catalog's *documented availability* on JMP 18. They do not establish identical default behavior, parser acceptance of every renderer expression, or native success on Pro 18.

The first isolated Pro 18 run passed initial column identity/count, four rows/values, Numeric/Continuous role, Distribution, stored script, table save/close/reopen, report rerun and independent displayed statistics comparison. The generated script's status deliberately says `sourceRecordingCompared=false`; the primary agent's independent GUI comparison is documented separately, not attributed to the user. Bivariate, Fit Line, changed-data and Pro-only analyses have not been executed on Pro 18. Do not reinterpret this small successful sample as broad native support.
