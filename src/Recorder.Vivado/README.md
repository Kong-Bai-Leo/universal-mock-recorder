# Vivado Recorder

Independent Windows executable. Run inside the same VM/session as Vivado 2024.2, never on the outer RDP client. Captures target-process mouse/keyboard, optional UI Automation, before/after and delayed screenshots. Does not read HDL, project files, Tcl journal or clipboard. Close sensitive windows: screenshots cover the desktop.

Start → perform a small workflow → wait for visible completion → stop. Recordings are saved beside the executable. Prepare is local; Analyze uploads only the listed recording evidence to the configured OpenAI provider. Every round is capped at two requests, twelve images per request and 6000 output tokens; no automatic retries. Unknown/failed request requires explicit retry. Complete checkpoints are reused.

Primary output: **vivado-replay.tcl**, one self-contained file to run directly in Vivado. Generation always compiles the validated model-selected interfaces to Tcl; the model still returns structured calls internally. `_internal/replay-plan.json` is an audit artifact, not a file the user must execute or pass to another AI. Copy only the Tcl to the target machine: it does not need JSON, the recorder, Node.js or an API key. Exact captured HDL, when supported, is embedded and written by the script. First release is bounded to new RTL project configuration and fully visible HDL. IP, block diagrams, hardware, arbitrary properties/scripts and unseen source content are unsupported.

Run the empty-project configuration sample: close the current project, then **Tools > Run Tcl Script** and select `vivado-replay.tcl` ([AMD Vivado 2024.2 manual](https://docs.amd.com/r/2024.2-English/ug893-vivado-ide/Running-a-Tcl-Script-from-the-Vivado-IDE)). The script creates a new UUID-named folder under Vivado's current working directory and refuses to overwrite an existing destination. Use a writable working directory. Synthesis/implementation execution is still unverified; GUI interactive `wait_on_runs` is not a completion guarantee. Do not equate script generation with a passed native replay.

After successful analysis the recorder shows **打开脚本位置**, not raw response JSON. Budget-paused or incomplete analysis must not be displayed as a finished script. Local evidence, provider records and checkpoints remain for diagnostics; they are not required at replay time. The legacy `--export-validation-tcl` CLI flag is accepted but no longer required and does not generate a second script.

Build: scripts/build-vivado-recorder.ps1. Analyze: scripts/analyze-vivado-recording.ps1 -Recording <directory> -PrepareOnly, then -Analyze. Existing completed responses can be compiled offline through the CLI --compile-saved-run mode. No keys are included in packages. Configuration and API key are local only; do not copy .env to a VM or commit recordings.

PowerShell also supports `-CompileSavedRun <completed-run-folder>` for zero-request script regeneration, or `-Analyze -RetryFailed -ResumeSavedRun <previous-run-folder>` for explicitly authorized failed-chunk recovery. Offline compilation validates original evidence and provider provenance, leaves paid responses unchanged, and writes a new `offline-compile-*` directory.
